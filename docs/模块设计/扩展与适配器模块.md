# Code Review Agent 扩展与适配器模块详细设计

## 1. 文档状态

- 日期：2026-09-10
- 状态：设计完成，待复审
- 关键裁决：本设计替代 Review Tool 使用 Python packaging entry point 的早期方案

## 2. 设计结论

系统分别维护 Input、Model、Review Tool、Output 四个 Registry。Registry 只负责声明校验、注册、冲突、能力匹配、选择和版本固定，不执行工作流。

Input、Model、Output 是应用维护者信任、依赖锁定并随应用发布的代码，不提供运行时任意 Python 插件。Review Tool 只能是 TOML/JSON 数据，由系统受限解释器执行。

## 3. 共同声明、注册与固定

声明包含 kind、稳定 ID（即架构 9.5 要求的稳定名称/机器标识，显示名仅用于人读展示）、版本、contract version、显示名、固定能力、**required_system_capabilities（所需系统能力，对应架构 9.5 与依赖规则 10：Input/Model 声明定向网络与凭证能力，Output 声明当前任务受限交付目标，Review Tool 声明"无任何系统能力"）**、支持输入/语言、limits、failure impact、origin、resource/schema digest。禁止凭证、任意 URL、Python 对象路径、entry point、回调、shell、文件通配、环境变量、仓库路径和未知能力；未知字段默认拒绝。

注册流程为读取内置清单/锁定资源、schema 校验、规范化、摘要、冲突和能力自检、生成 RegistrySnapshot、freeze。能力自检必须核对所需系统能力与注册器授予的最小能力集合一致（不多于也不少于声明），超声明能力在注册期拒绝。同 kind/ID/version 唯一；同身份不同摘要、别名多义、contract 主版本不兼容均失败，不覆盖。

TaskSpec 固定选择的身份、版本、contract、能力、origin、资源摘要及适配器/解释器版本。恢复逐项核对，不重新选择或自动 fallback。

## 4. 四类 Registry

Input MVP 为 plain diff、GitHub.com、GitLab.com；能力包括身份规范化、固定版本获取、完整性证明、固定 SHA 文本读取和错误映射。仅获得定向网络与凭证。

Model 注册 OpenAI、Anthropic、OpenAI-compatible；声明上下文、结构化输出策略、最终请求 token 计数/上界、最大输出硬限制、usage 映射、禁重试和非流式。预算、安全、Trace 和重试不属于 Provider。

Output MVP 仅本地 Markdown；接收不可变 ReportModel，固定模板渲染、复扫、原子替换和 inspect。不能查询可变业务表或远程发布。severity 可内部保存，但 MVP Markdown 不展示严重度标签。

Review Tool 只从应用内置或发布物锁定资源加载，不从仓库、工作目录、环境变量任意路径、entry point 或网络加载。

## 5. 规则语言与受限解释器

工具声明包含 ID/version/contract/languages/rule set/deterministic/failure impact/limits/rules。limits 覆盖输入字节、token、规则、步骤、匹配、输出项、字段长度和软时间。

允许 op 仅为 `literal_contains`、`literal_not_contains`、`token_sequence`、`token_pair_within`、`line_predicate`、`line_prefix`、`line_suffix`、`line_equals`、`balanced_delimiter`、`changed_line_only`、`bounded_context_contains`、`identifier_equals`、`call_name_equals`、`argument_literal_equals`。

`line_predicate` 只接受固定字面量参数，语义限定为"整行是否精确等于、或以其为前缀/后缀匹配给定的字面量集合"（等价于 `line_equals`/`line_prefix`/`line_suffix` 的组合，其中 `line_equals` 为整行精确匹配字面量），不允许任意行级布尔表达式、函数式谓词或动态求值；其参数在声明加载时静态校验为常量字符串集合，运行时无任意表达式能力。

禁止通用正则、glob 语言、任意表达式、eval/exec、模板、动态导入、Python 回调、shell/进程、网络、数据库、keyring、环境变量、通用文件读取、仓库配置、递归和无界循环。

解释器仅接收计划授权且已安全处理的 UTF-8/LF/NFC 文本视图，保留行数和新旧侧坐标。token 化、排序和摘要按版本固定；相同解释器、规则、输入、范围和 limits 必须产生相同摘要。硬上限触发时整个尝试失败，不返回截断成功或局部证据。

成功证据记录 tool/rule/interpreter 版本、输入摘要、路径、scope、位置、op 参数摘要、匹配安全摘要、步骤、序号、结果摘要和 Trace；输出先经安全门禁再校验持久化。

## 6. 失败、组合根与契约

声明无效、未知 op、越权或冲突在注册期拒绝。输入超限为 blocked；步骤/匹配/输出/时间超限为 failed_known；中断为 interrupted；摘要不稳定为 determinism_violation 并停用该版本。失败不能冒充验证成功，并按计划降低证据或覆盖。

唯一组合根创建 Registry、适配器、解释器、UoW 和应用服务。适配器之间不直接调用。

```text
register / freeze / select / resolve_exact
verify_fixed_reference / list_capabilities
RestrictedToolRuntime.execute(fixed_tool_ref, authorized_input,
                              planned_limits, execution_context)
```

执行上下文不含 repository、凭证、连接、环境变量或文件句柄。

## 7. 测试与 ADR

四类端口使用共享合约测试；Tool 额外覆盖全部 op、恶意声明、资源限制、确定性和证据。扩展性测试新增四类测试实现而不修改编排。架构测试禁止动态导入和适配器互调。

ADR-EXT-001：受信任适配器随应用发布。ADR-EXT-002：Review Tool 使用声明式有限语言。ADR-EXT-003：任务固定精确版本和摘要。
