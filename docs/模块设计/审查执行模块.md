# Code Review Agent 审查执行模块详细设计

## 1. 文档状态

- 日期：2026-09-10
- 状态：设计完成，待复审
- 上游依据：《架构设计.md》及任务、安全、输入、规划模块设计
- 适用范围：单进程、串行工作单元、声明式工具、每次工作单元执行至多一次模型调用

## 2. 设计结论

采用“显式阶段管线 + 只追加尝试 + 候选发现边界”：

```text
固定 WorkUnit → 安全解析输入 → 按计划执行工具
→ 安全处理工具结果 → 构造并扫描最终模型请求
→ 原子预算预留/调用/Trace → 单次模型调用
→ 入站安全处理 → 结构化候选发现
→ 原子结算/候选/checkpoint → WorkUnitExecutionResult
```

不存在 Agent Loop、模型动态工具调用、隐式重试、自动修复输出、模型切换或自动追加预算。每个 `WorkUnitExecution` 至多关联一个 `ModelCallAttempt`；显式重试创建新的 execution 和 model attempt，并继续绑定原 `work_unit_id`。

## 3. 职责边界

模块负责执行一个固定工作单元、记录工具与模型尝试、构造 `PromptEnvelope`、解析候选发现和产生提交意图。它不创建计划、不最终验证发现、不定级、不去重、不生成快照/报告、不直接修改任务或预算。

## 4. 领域模型

### 4.1 WorkUnitExecution

包含 execution/task/work unit/plan 身份与版本、attempt number、状态、输入引用、计划工具、模型策略、prompt 规格、尝试引用、候选引用、覆盖影响和时间。

状态为 `pending → running → succeeded | partial | failed | unknown`。`partial` 表示已有可复用结果但验证或覆盖受损；`unknown` 只用于外部模型结果不明。新尝试必须由显式恢复创建。

覆盖投影（供规划 5.2/发现处理 3.3 使用）对 WorkUnitExecution 的终态判定：`succeeded` 且对应范围全部真实完成 → 投影 `reviewed`；`partial`（覆盖受损）、`failed`，或 `succeeded` 但 `response_state=invalid_output/security_rejected`（模型成功但无有效候选，范围未真正覆盖）→ 投影 `unreviewed` 并在原因码中区分；`unknown` → 投影 `unknown`。不得把"输出无效/被拒绝/覆盖受损"的单元投影为 `reviewed`。

### 4.2 ToolAttempt

包含固定 invocation、tool/规则版本与摘要、输入摘要、安全输出引用、证据 ID、资源使用、Trace 和标准错误。状态为 `pending → running → succeeded | failed_known | blocked | interrupted`。

工具是系统受限运行时执行的声明式规则，不访问网络、凭证、数据库、环境变量、进程或通用文件系统。相同工具版本、规则摘要和输入摘要必须产生相同规范输出摘要，否则为确定性违约。

### 4.3 ModelCallAttempt

包含 Provider/模型/prompt/输出 schema、结构化输出策略、请求/响应安全引用、请求摘要、预算预留、usage、Trace 和错误。

模型调用使用两个正交状态轴，避免供应商调用事实、响应安全处理和业务解析互相覆盖：

```text
provider_state:
pending → reserved → running → succeeded | failed_known | unknown

response_state:
not_available → pending → accepted | invalid_output | security_rejected
```

预算只依据 `provider_state`、可靠 usage 和预留结算；候选生成依据 `response_state`。Provider 成功但响应 schema 无效时为 `succeeded + invalid_output`；Provider 成功但入站门禁拒绝时为 `succeeded + security_rejected`。`security_rejected` 的 usage 结算仍按预算模块契约执行：响应正文被安全模块拒绝不免除可信 usage 的结算，usage 不可信时按预留或报告值保守计入（见预算模块 §5.6/§8），不能因响应被丢弃而忽略实际消耗。Trace 同时记录两轴，`model.response_rejected` 是响应处理事实，不改写 Provider 调用事实。不确定消耗的触发条件为 `provider_state=unknown`，或 Provider 已确认成功但 usage 缺失/不可信（预算 §8，usage_state=missing/untrusted）；其中只有 `provider_state=unknown` 触发人工确认重试，succeeded+usage 不可信不自动重试也不要求人工确认。

### 4.4 PromptEnvelope

`PromptEnvelope` 是供应商无关、不可变的请求语义：系统审查规则、工作单元定位、处理后 diff、受控上下文、工具事实、输出 schema、禁止能力说明和版本摘要。它不包含凭证、动态工具、任务命令或模型内部推理要求。

Provider 适配器把它转换为最终请求后，最终序列化字节仍须经过模型出站安全检查；预算估算与预留针对实际最终请求。

### 4.5 CandidateFinding

候选发现至少包含 candidate/task/work unit/execution、来源、类别、标题、问题、触发条件、候选位置、证据引用、影响、修复建议、变更因果说明、限制、Trace 和 schema 版本。

候选位置支持 `new_line`、`old_line`、`file`、`multi_file`。候选只做结构校验；路径/行号真实性、证据充分性、范围、严重度和置信度由发现处理模块裁决。模型自述置信度仅可作为审计字段，不能成为系统等级。

### 4.6 EvidenceReference

证据引用包含稳定 evidence ID、类型、来源产物/工具/模型尝试、位置、内容摘要、安全证明和 Trace span。候选只能引用本次执行实际提供或产生的材料，禁止自由文本声称“工具已验证”。

## 5. 工具执行

执行模块严格按计划中的有序 `PlannedToolInvocation` 运行，不得新增、替换、提权或根据模型结果再运行工具。每次尝试先提交 running 事实，再由受限运行时处理授权文本，输出先过安全门禁，再原子保存结果、Trace 和工具 checkpoint。

可选工具失败可继续但形成证据降级；影响覆盖的工具失败使单元 partial。`blocked` 与 `failed_known` 按扩展模块 §6 的规则区分：输入超限或声明越权（未执行）记 `blocked`，执行后步骤/匹配/输出/时间超限或结果 schema 无效（已执行）记 `failed_known`；二者都绝不能显示为验证成功。本地确定性尝试中断可在恢复时创建新尝试，不覆盖旧事实。

## 6. 模型调用原子边界

1. 构造最终请求并取得安全证明；
2. **准备事务**：预算预留、调用记录、脱敏请求 Trace、工作单元关系；
3. **开始标记**：外部 I/O 前置为 running；
4. 调用 Provider 一次，禁用 SDK 自动重试和流式输出；
5. 响应先入站安全处理，再做结构化解析；
6. **完成事务**：安全响应/标准错误、usage 结算、调用终态、候选结果、覆盖影响和 checkpoint。

准备失败不调用模型；开始后到完成事务间中断使 `provider_state=unknown`，保留最坏预留，不自动重试。实际 usage 超预留时如实结算、产生预算异常并冻结后续调用。预算不足、预算异常或 unknown 的原子事务只提交调用/预算事实、执行结果、覆盖影响、checkpoint 和“需要收敛结果”的任务意图，不直接创建 ResultSnapshot。

## 7. 结构化输出策略

优先级固定为任务创建时的能力选择：原生 JSON Schema → tool calling → JSON 文本 + 严格 schema 校验。执行时不得自动降级到另一策略。未知字段、缺失必填字段、超限数组、非法位置组合或非 JSON 内容返回 `invalid_output`；不得用隐藏模型调用修复。

系统不保存或要求模型内部思维过程，只保存结构化结论、实际请求/响应的安全版本和可核对证据。

## 8. WorkUnitExecutionResult

输出包含 execution/work unit、状态、候选引用、成功/失败工具尝试、模型调用、覆盖影响、未解决证据、标准错误、checkpoint 意图和 `TaskTransitionIntent`。它不是最终审查结果，不包含最终置信度或任务结果状态。

## 9. 恢复语义

- 已完成工作单元 checkpoint：直接复用；
- 尚未开始：正常执行；
- 本地确定性步骤中断：可重做当前单元或工具并保留旧尝试；
- 模型 `reserved` 且未开始：可释放预留后新建尝试；新尝试属于新的 `WorkUnitExecution` 和新的 `ModelCallAttempt`，与原 execution/attempt 不共享模型尝试标识，以维持"每个 `WorkUnitExecution` 至多一个模型尝试"的不变量（与 `running`/`unknown` 情形一致，均为显式恢复或策略允许下创建新 execution）；被放弃的原 execution（请求未发送、预留已释放）以 `failed` 终态收敛并记录"预留已释放、未调用模型"，不触发 unknown 或不确定消耗；
- 模型 `running` 无完成事务：转 unknown，用户明确确认且预算允许后创建新的 `WorkUnitExecution` 和 `ModelCallAttempt`；旧 execution 和尝试保留，不覆盖；
- 模型明确失败：由编排根据策略决定暂停或显式恢复；
- 相同 candidate/finding 不因恢复重复，由稳定来源和后续 fingerprint 合并。

## 10. 公开端口

- `ReviewExecutor.execute(ExecutionRequest)`；
- `RestrictedToolRuntimePort`；
- `ModelGatewayPort`；
- `SecurityBoundaryPort`；
- `BudgetPolicyPort`；
- `TraceIntentPort`；
- `ExecutionArtifactRepository`；
- `PersistenceUnitOfWork`。

所有 Provider/工具异常必须在适配器边界映射，领域层不解析异常文本。

## 11. 错误与降级

稳定错误包括 `work_unit_mismatch`、`tool_unavailable`、`tool_blocked`、`tool_invalid_result`、`model_capability_mismatch`、`budget_reservation_rejected`、`model_failed_known`、`model_result_unknown`、`model_output_invalid`、`security_boundary_failed`、`persistence_integrity_failed`。

工具失败、预算不足和部分内容跳过可形成 partial；安全失败、固定条件不一致和持久化完整性失败必须停止新的外部调用。

## 12. 关键不变量

1. 一次执行只绑定一个固定工作单元；
2. 工具集合、顺序和能力不可动态改变；
3. 每个 `WorkUnitExecution` 最多一个模型尝试；同一 WorkUnit 的显式重试创建新 execution；
4. 模型请求先安全检查和预算预留；
5. 响应先安全处理再解析或持久化；
6. unknown 不自动重试；
7. 候选只能引用实际材料；
8. 候选不能直接进入报告；
9. 模块不直接修改任务、预算或 Trace；
10. 调用完成、预算结算、候选和 checkpoint 原子提交。

## 13. 测试与需求映射

- 工具合约与恶意声明测试；
- Prompt 与候选 schema 单元/性质测试；
- 模型三种结构化策略、usage 缺失/超额和异常映射测试；
- 安全测试覆盖 prompt、上下文、工具结果和模型回显；
- 故障注入覆盖预留、running、响应、扫描和完成事务；
- 工作流测试证明无隐式重试、unknown 暂停和已完成单元复用。

主要覆盖 FR-005～FR-006、FR-011～FR-019、FR-021～FR-028。

## 14. 设计决策

- 工具先于模型并由计划固定，避免动态 Agent 权限与恢复歧义；
- 每单元至多一次模型调用，便于预算硬约束和 unknown 处理；
- 候选发现与最终发现分离，防止模型输出绕过确定性验证；
- 两阶段调用事务承认外部 I/O 无法与 SQLite 原子化，并以 unknown 保守收敛。

## 15. 设计结论

审查执行模块把单个工作单元转化为有事实 Trace、硬预算和安全证明的候选发现；所有工具和模型行为显式、有限且可恢复，但任何候选都必须经过发现处理后才能成为用户评论。
