# Code Review Agent 基础设施模块详细设计

## 1. 文档状态

- 日期：2026-09-10
- 状态：设计完成，待复审
- 上游依据：《架构设计.md》及现有全部模块详细设计
- 适用范围：Python 3.12、本地 CLI、单进程、单机 SQLite、可信 OS 账号

## 2. 设计结论

基础设施以端口适配器实现 SQLite、keyring、文件系统、GitHub/GitLab、模型、安全扫描和 Markdown 交付。核心层不接触连接、SDK 对象或第三方异常。

SQLite 是结构化状态的唯一事务存储，跨模块写入共用 `PersistenceUnitOfWork`。文件和外部 I/O 使用“尝试记录 + running + 完成事务/unknown 核对”收敛。未安全处理的原文不得落盘。

## 3. 目录、文件与迁移

platformdirs 提供 `config/config.toml`、`data/state.sqlite3`、`reports/<task_id>.md` 和可删除 cache。配置仅存非敏感值和凭证别名。拒绝符号链接、非常规文件、非当前账号所有或权限过宽的关键路径；数据不写入受审仓库。

报告适配器以规范化目标为键取得跨执行者排他文件锁，在同一临界区内重新核对当前 task version、snapshot、交付租约与 fencing token，再于目标同目录创建任务专属临时文件。完整写入、flush、fsync 后，适配器在 `os.replace` 紧邻执行前再次核对这些条件，替换后同步父目录并核对身份和 SHA-256，最后以相同条件提交交付终态。锁覆盖检查、替换、核对和终态提交；失去租约或持有旧 fencing token 时放弃临时文件且不得替换。只清理可证明属于应用且无活动 DeliveryAttempt 的过期临时文件。

SQLite 连接核对 `foreign_keys=ON`、`journal_mode=WAL`、`synchronous=FULL`、`busy_timeout=5000`、`trusted_schema=OFF`。写事务使用 `BEGIN IMMEDIATE`；参数绑定；UTC 时间；JSON 只保存版本化白名单结构。

迁移文件按 `NNNN_name.sql` 递增并内嵌校验和。`schema_migrations` 与 `PRAGMA user_version` 必须一致。备份目录包含独立于主 SQLite 的固定格式 `backups/manifest.json` sidecar，不把备份清单保存在被迁移数据库中。manifest 使用规范 JSON、schema 版本和条目摘要，目录、manifest、备份及临时文件均拒绝符号链接且仅当前账号可访问。

迁移协议固定为：停止业务写并核对无活动事务；创建同目录不可预测临时备份并 `fsync`；核对 SQLite 完整性与摘要后原子改名；以“旧 manifest + 新 pending 条目”生成临时 manifest，`fsync` 后原子替换并同步父目录；只有 manifest 已提交才开始主库迁移。启动恢复扫描目录：有备份无 manifest 条目时按摘要验证后补记 orphaned，pending 且主库仍为源 schema 时可安全重试/删除，pending 且主库为目标 schema 时核验后标记 succeeded，无法判断则阻止启动并要求维护。成功迁移完成完整性检查后将条目置 succeeded。备份默认最多保留 7 天且最多 3 份；失败迁移保留最近一份直到用户显式处理。过期备份由维护用例先把 manifest 条目置 deleting，再删除文件并同步目录，最后置 deleted；任一步结果不明均可按 manifest 和文件摘要恢复，不得宣称已清除。

迁移备份是数据库的完整副本，不能实现按任务删除。sidecar 每个备份条目保存备份时数据库中仍存在的 `retention_group_id` 集合或其无假阴性的固定索引摘要；索引缺失、损坏或无法证明任务不在备份中时按“包含目标任务”处理。`CleanupTask` 通过 `BackupManifestPort` 检查覆盖该任务详细数据的未过期备份：存在时返回 `cleanup_blocked_by_backup` 并列出安全备份 ID/到期时间，除非用户先通过显式维护命令删除这些备份；不得在当前数据库清理后仍声称任务详细数据已清除。备份不进入普通 cache 清理，也不得复制到报告目录或受审仓库。

## 4. SQLite schema

所有详细表带适用的 task ID、schema version、UTC 时间、content digest、retention group 和安全引用。枚举用 CHECK；数据库禁止凭证、认证头、第三方异常正文及未处理 diff/prompt/响应/工具输出。

| 分组 | 表 | 关键约束 |
| --- | --- | --- |
| 迁移 | 主库 `schema_migrations` + 独立 `backups/manifest.json` | version PK；name/checksum 不可漂移；sidecar 在主库不可读时仍可恢复，备份状态与摘要可核对 |
| 任务 | `task_requests`、`control_command_receipts`、`tasks`、`task_specs`、`task_leases`、`execution_sessions`、`stop_requests` | 创建/控制命令幂等；控制回执位于任务保留组外；三轴状态正交；spec 只读；单有效租约；fencing 单调 |
| 恢复 | `work_item_attempts`、`checkpoints`、`result_snapshots`、`cleanup_attempts`、`task_tombstones` | attempt 只追加；task/sequence 和 snapshot version 唯一；清理全有或全无 |
| 输入 | `input_acquisitions`、`input_artifacts`、`input_completeness_proofs`、`input_bindings`、`change_sets`、`change_files`、`change_hunks` | task 至多一 binding；complete proof 才能绑定；内容只存安全引用 |
| 规划 | `review_plans`、`review_work_units`、`work_unit_tools`、`coverage_scopes` | task 一个冻结计划；scope 不重不漏；工具不可变 |
| 执行 | `work_unit_executions`、`tool_calls`、`model_calls`、`candidate_findings` | 重试新 execution；每 execution 至多一模型调用；provider/response 双轴 |
| 发现 | `coverage_snapshots`、`coverage_snapshot_scopes`、`finding_sets`、`findings`、`finding_sources` | coverage snapshot 与范围明细不可变且版本化；绑定同一冻结计划、执行事实边界和 consolidation checkpoint；set 只引用 snapshot；finding fingerprint 在同一任务/同一 FindingSet 版本内唯一，位置和直接证据必填 |
| 预算 | `budget_accounts`、`budget_authorizations`、`budget_reservations`、`budget_ledger`、`budget_freezes`、`provider_budget_capabilities` | task 唯一账户；账本 sequence；call 唯一 reservation；单 active freeze |
| 安全 | `security_policies`、`security_attestations`、`sanitized_artifacts`、`artifact_provenance`、`security_events`、`policy_compatibility` | 证明只追加；用途/摘要不可改绑；provenance 同任务无环 |
| Trace | `trace_events`、`trace_edges`、`comment_trace_links`、`trace_intents`、`trace_integrity_checks` | task sequence/幂等键唯一；边同任务；finding 当前 link 唯一 |
| 报告 | `delivery_attempts`、`report_artifacts`、`delivery_target_locks` | 绑定确切 snapshot；`delivery_key` 由 `(task_id, snapshot_id, adapter_id, adapter_version, normalized_target, expected_content_digest)` 规范派生并幂等唯一；规范化目标锁跨执行者排他并携带 owner、租约、fencing 和过期时间；任务目标路径独立约束；旧快照尝试不得阻止新快照尝试或覆盖新状态 |

核心索引覆盖任务状态/过期时间、checkpoint sequence、work unit ordinal、execution/work unit、model provider state、coverage snapshot task/version 与 scope 分类、预算 sequence/active reservation、Trace task/finding/call、报告 task/snapshot/state 和 retention group。部分唯一索引保证单有效租约、单 active freeze 和当前 TraceLink。

## 5. PersistenceUnitOfWork

UoW 只接收类型化 Intent，不接受任意 SQL：规范化和摘要；检查幂等；`BEGIN IMMEDIATE`；读取 task/version/lease/fencing/预算 revision；校验安全和跨任务引用、状态迁移、账本、Trace sequence、checkpoint 前驱；按固定拓扑写入；执行一致性查询；保存幂等结果；commit 并返回新版本。

StopRequest 使用独立控制事务与 `stop_revision` 唯一约束，不更新 tasks 行；任务执行 UoW 携带 `observed_stop_revision`，并在同一 SQLite 写事务中拒绝越过更新的 pending/observed 请求。`stop_convergence` 租约仍通过 tasks/task_leases 的条件事务取得并产生更高 fencing token。

BackupManifestPort 只操作 sidecar manifest，不加入业务 UoW。它使用位于 backups 目录的跨进程排他锁，备份创建、manifest 恢复/更新/删除及 CleanupTask 的“核对 manifest → 数据库删除事务提交”全程持有同一把锁。CleanupTask 持锁读取并核验 manifest generation，执行数据库删除事务前再次比较 generation；直到数据库 commit 后才释放锁，因此迁移进程不能在检查和清理提交之间创建新备份。锁持有者崩溃由 OS 自动释放；锁文件本身不承载状态，恢复仍以 manifest 和备份摘要为准。备份删除与 SQLite 控制回执采用可核对状态机而非伪装成跨文件/数据库原子事务：先提交 manifest deleting，再删除并同步文件，随后提交 manifest deleted，最后幂等写入控制回执；任一中断由相同 request ID、manifest 状态和文件摘要恢复。

失败全部 rollback。提交响应丢失时以同一幂等键查询，不盲目重做。Repository 只提供聚合/用例所需查询，不暴露裸连接、通用 execute、跨任务 payload join 或 append-only 表更新入口。

## 6. keyring 与文件权限

CredentialStorePort 提供 set/get/clear/exists；服务名固定，账号键由 credential alias 和 Provider ID 派生。secret 不进入 DTO、日志或 repr。无安全 backend 时失败，不回退明文。

环境变量只作为显式运行时注入，不写回 keyring/SQLite。任务固定 alias 而非 secret 摘要；Provider 在最短作用域读取。数据库、配置、报告和临时文件默认仅当前账号可读写。

## 7. GitHub/GitLab 适配器

GitHub 使用 PyGithub，GitLab 使用 python-gitlab；SDK 不完整端点由 Provider 内受限 HTTPX 补齐。固定 HTTPS 官方 API host，禁跨主机重定向、环境代理继承和自动 retry，并限制连接、读取、总响应大小。

GitHub 完整遍历 PR 文件分页并固定 base/head；GitLab 使用 `/diffs`，必要时 `/raw_diffs`，拒绝 collapsed、too_large、overflow 和缺页。上下文只按固定 SHA 和规范路径读取。SDK/HTTP 异常映射稳定码，原始响应和认证头不离开适配器。

## 8. 模型 Provider

项目自有 OpenAI、Anthropic 和 OpenAI-compatible Provider adapter 负责协议转换，不使用 LangChain ChatModel 或供应商 SDK 的高层发送接口。`prepare_request()` 构造完整不可变的 method/origin/path/body 字节并返回摘要、token 精确值/安全上界和最大输出硬限制证据；`send_prepared()` 通过受限 HTTPX transport 原样发送，除绑定固定 origin 的认证头外不得重新序列化或注入默认字段。调用一次后 adapter 归一化 provider state、响应元数据和 usage；自动 retry、fallback 和 streaming 均关闭。

ModelGateway 配置并强制连接、读取和总调用三类 deadline；三者都必须显式配置为有限正值，且总 deadline 不得小于连接或读取 deadline，并与执行租约和续约策略共同校验，不能依赖 SDK 默认值或无限等待。取消或任一 deadline 到达后，只有能证明请求尚未发送时才返回 `failed_known` 并释放预留；请求已发送或是否发送无法证明时必须返回 `unknown`，保留保守预算占用并进入既有显式确认恢复流程。

ModelGateway 与审查执行模块的模型端口共同承担架构 §6 规则 8 的统一模型网关职责，边界如下：ModelGateway 负责供应商请求的构造/发送核对、三类 deadline 强制、Provider 状态归一化，以及预算占用/释放的调用面触发；预算预留、安全检查与脱敏、Trace 记录和调用状态迁移不在此类 deadline 判断中自行绕过，而是通过 `PersistenceUnitOfWork` 的调用准备/开始/完成事务由预算、安全和 Trace 模块强制原子承载（见审查执行模块 §6）。ModelGateway 不直接写 SQLite，也不把供应商异常当作领域错误。

OpenAI-compatible 只承诺标准 Chat Completions。reasoning 字段不进入领域对象。无法保证最终请求一致、输出硬上限或 usage 可信映射时，不兼容硬预算。请求可能发送后的 transport 超时返回 unknown；明确发送前失败才释放预留。

## 9. 安全与输出适配器

detect-secrets 只启用固定 detector，关闭网络验证，拒绝仓库 baseline、allowlist、过滤器和插件；项目规则补充连接串、证书、PII 和业务敏感标记。适配器只返回白名单命中，安全核心决定 safe/redacted/blocked/indeterminate。

Jinja2 只加载应用固定模板，使用 StrictUndefined 和固定过滤器，禁动态 include、仓库模板和任意表达式。Markdown adapter 接收 ReportModel；severity 为内部字段，MVP 模板不展示严重度标签。最终 UTF-8 字节以 report_delivery 用途复扫后才能写入。

## 10. 错误、测试与 ADR

稳定错误族包括数据库 busy/integrity/migration、credential unavailable、平台 auth/permission/rate-limit/temporary/incomplete、模型 failed_known/unknown/usage_untrusted、文件 permission/write/unknown 和 scanner unavailable。错误仅含阶段、稳定码、可恢复性和安全关联 ID。

测试使用临时 SQLite 验证 FK/unique/check/index/migration，故障注入覆盖每个 UoW，双连接验证版本/fencing/stop revision 提交门禁，fake keyring，respx 验证分页/重定向/超时/截断，模型 fake 验证三种结构化策略、usage、unknown 和实际 wire body 与 prepared digest 一致，并扫描数据库、迁移备份、日志和报告无未处理 secret。迁移测试还使用两个进程验证 sidecar 锁、崩溃恢复、备份权限、数量/期限、cleanup 与备份创建互斥、清理阻断和显式删除。

ADR-INFRA-001：sqlite3 + 显式迁移。ADR-INFRA-002：跨模块共享 UoW。ADR-INFRA-003：文件副作用采用核对式收敛。ADR-INFRA-004：平台 SDK 优先、受限 HTTPX 补齐。ADR-INFRA-005：模型使用自有 wire adapter 和原样 HTTP transport。ADR-INFRA-006：迁移备份纳入显式保留与清理门禁。
