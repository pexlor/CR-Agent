# Code Review Agent 安全模块详细设计

## 1. 文档状态

- 日期：2026-09-10
- 状态：设计完成，待复审
- 上游依据：《需求拆解.md》《验收清单.md》《技术选型.md》《架构设计.md》《模块设计/任务模块.md》
- 适用范围：本地 CLI、单进程、同一可信操作系统账号、只读审查

本文设计安全核心模块及其公开契约。keyring 凭据适配、声明式 Review Tool 受限运行时、SQLite 物理表结构、平台和模型 SDK 的内部实现由后续模块详细设计负责；本文固定这些模块不可绕过的安全边界。

## 2. 设计结论

安全模块采用“策略决策核心 + 不透明安全证明 + 外围扫描适配器”的方案：

- 所有不可信文本在模型出站、领域接收、跨模块传递或持久化前经过统一安全门禁；
- 安全处理结果不以裸字符串表示，而以 `SanitizedArtifactRef` 引用持久化的安全证明；
- 调用方不能通过自行构造字段声明内容已安全，持久化工作单元必须核对安全证明；
- 原始内容只允许在受控内存作用域内存在，不进入任务、Trace、checkpoint、日志、错误或报告；
- 仓库内容、外部响应和模型输出始终是数据，不能产生系统能力、改变配置或触发控制操作；
- 扫描器不可用、策略不完整、结果不确定或证明无法核对时一律失败关闭；
- 恢复时允许使用更强策略，但旧产物必须经过兼容性判断，必要时重新扫描。

该方案不引入加密数据库、独立沙箱进程、账户系统或通用数据防泄漏平台。

## 3. 目标

安全模块必须保证：

1. 敏感数据不会被发送给模型或以明文进入本地持久化产物；
2. 外部响应在进入领域模型、Trace 或持久化前已完成安全处理；
3. 每个可持久化业务 payload 都能证明由哪一版策略、哪个扫描器集合、以何种结果处理；
4. 安全处理不能由调用方关闭、降级、伪造或先写后补；
5. 仓库内容和外部返回不能授予网络、凭据、文件、进程、预算、任务或发布能力；
6. 安全事件可审计，但安全日志本身不成为泄漏通道；
7. 处理失败时能够明确区分可跳过范围与整个安全边界失效；
8. 策略升级后能够判断旧产物是否可继续使用。

## 4. 非目标

本模块不负责：

- 管理用户、组织、角色或 RBAC；
- 对 SQLite 或报告文件做应用层加密；
- 保存、轮换或读取 keyring 中的凭证值；
- 判断 GitHub、GitLab 或模型供应商凭证是否具有平台侧最小权限；
- 实现 Review Tool DSL、步骤限制或解释器；
- 执行杀毒、依赖漏洞扫描、SAST、构建、测试或 typecheck；
- 证明任意自然语言 prompt injection 已被准确识别；
- 执行远程回评、代码修改、提交、合并或其他外部写操作；
- 将目标仓库的 baseline、allowlist、插件或过滤器作为安全策略输入；
- 为未来多用户、服务化或分布式运行提供隔离保证。

## 5. 威胁模型与信任边界

### 5.1 受保护资产

- GitHub、GitLab 和模型供应商凭证；
- diff、仓库上下文及其中的业务敏感信息；
- 模型请求、模型响应和工具结果；
- Trace、checkpoint、错误、日志和报告；
- 固定任务规格、预算、状态、恢复和发布控制权；
- 本机文件、环境变量、网络和进程能力。

### 5.2 信任主体

| 主体 | 信任级别 | 允许能力 |
| --- | --- | --- |
| 组合入口与应用核心 | 受信任 | 装配固定策略和端口，调用领域用例 |
| 维护者安装的 Input/Model/Output Adapter | 受限信任 | 仅获得职责所需的定向网络、凭据或交付目标 |
| 安全扫描适配器 | 受限信任 | 在进程内读取待检查内容并返回结构化命中，不得联网 |
| 当前 OS 账号下的显式 CLI 操作 | 受信任控制输入 | 创建、恢复、追加预算、管理凭据和清理 |
| 目标仓库内容 | 不可信数据 | 不获得任何系统能力 |
| 平台、工具和模型返回 | 不可信数据 | 必须先经过入站门禁 |
| 声明式 Review Tool 规则包 | 不可信声明数据 | 仅由受限运行时解释，不获得 Python 执行能力 |

“受信任 Adapter”只表示其代码随应用安装和审查，不表示其返回内容可信，也不允许 Adapter 绕过安全、预算、Trace 或任务状态。

### 5.3 明确攻击场景

- diff、注释或 Markdown 中嵌入 API Key、私钥、连接串或个人信息；
- 删除行、上下文行、文件路径、异常文本或模型回显泄漏敏感值；
- 仓库文本要求模型忽略系统规则、读取环境变量、调用工具或改变报告目标；
- 恶意 URL 利用 userinfo、重定向或自定义 `base_url` 获取凭证；
- 第三方 SDK 把认证头、请求体或响应体写入调试日志；
- 调用方自行构造“已脱敏”对象绕过扫描；
- 策略升级后恢复任务继续复用按旧弱策略处理的内容；
- 扫描器崩溃、超时、返回冲突区间或无法处理编码；
- 脱敏占位符与原文混淆，导致报告或模型误认为占位符是真实代码。

## 6. 方案比较与裁决

### 6.1 方案 A：调用方约定式扫描

各模块在需要时自行调用扫描器并传递普通字符串。

优点是实现简单；缺点是无法证明所有路径都调用了扫描器，也无法阻止调用方把未处理字符串误标为安全。该方案不满足不可绕过和不可伪造要求，拒绝。

### 6.2 方案 B：安全核心与持久化证明

安全模块统一执行策略，产生不透明引用；原子持久化时核对证明，其他模块只能读取与用途匹配的安全产物。

优点是边界明确、可恢复、可审计，并能与任务工作单元原子提交；缺点是需要维护安全证明及用途约束。选择该方案。

### 6.3 方案 C：独立安全代理或沙箱进程

所有内容通过独立进程或本地服务处理。

隔离最强，但引入 IPC、进程生命周期、额外恢复状态和部署复杂度。当前单机 MVP 禁止执行仓库代码，扫描器为固定依赖，独立进程收益不足，暂缓。

## 7. 模块边界

### 7.1 安全模块拥有

- 安全策略定义、版本、摘要和兼容关系；
- 敏感类别、处理动作和失败规则；
- 内容来源、用途和信任标签；
- 扫描结果规范化、命中区间合并和脱敏决策；
- 安全证明及其生命周期；
- 仓库内容能力授权规则；
- 安全事件的白名单结构；
- 策略升级后的旧产物重验证规则。

### 7.2 安全模块不拥有

- 原始 diff、仓库文件、模型响应或工具输出的长期存储；
- 任务状态、预算流水、Trace 事实、报告正文和调用状态；
- keyring 凭证值；
- Provider URL 的业务配置；
- Review Tool 规则执行；
- SQLite 事务实现。

### 7.3 唯一安全决策规则

其他模块不能：

- 创建安全证明；
- 把普通字符串转换为 `SanitizedArtifactRef`；
- 将 `blocked` 或 `indeterminate` 结果改为允许；
- 覆盖策略版本、来源、用途、摘要或敏感类别；
- 使用为一个用途处理的产物替代另一用途的检查；
- 在安全证明提交失败后继续模型调用或持久化。

## 8. 核心领域模型

### 8.1 SecurityPolicy

`SecurityPolicy` 是不可变、版本化的策略，至少包含：

| 字段 | 含义 |
| --- | --- |
| `policy_id` | 稳定策略系列标识 |
| `policy_version` | 该系列中的不可变版本 |
| `schema_version` | 策略结构版本 |
| `policy_digest` | 规范化策略内容的 SHA-256 |
| `detector_manifest` | 固定 detector 名称、版本、配置摘要和实现摘要 |
| `sensitive_categories` | 策略识别的敏感类别集合 |
| `action_matrix` | 类别、来源、用途到处理动作的映射 |
| `limits` | 单产物大小、命中数、处理时间和输出大小上限 |
| `placeholder_format_version` | 脱敏占位符格式版本 |
| `created_at` | 策略发布时间 |

运行时只加载随应用安装并经过校验的策略。目标仓库、环境变量、模型响应和远程配置不能增加 allowlist、关闭 detector 或修改动作矩阵。

### 8.2 ArtifactDescriptor

每次安全处理都携带不可变描述：

- `artifact_id`：本次逻辑产物的 UUIDv4；
- `task_id`：可为空；任务创建前的配置校验不强制绑定任务；
- `source`：`user_cli`、`repository`、`platform_response`、`tool_output`、`model_response`、`trusted_application`；
- `trust_label`：`trusted_control_scalar`、`trusted_generated_metadata` 或 `untrusted_text`；
- `kind`：`diff`、`repository_text`、`path`、`prompt`、`model_payload`、`tool_payload`、`trace_payload`、`checkpoint_payload`、`error_payload`、`report_payload`、`log_payload`；
- `purpose`：`domain_ingress`、`model_egress`、`tool_ingress`、`persistence`、`report_delivery`、`user_display`、`security_log`；
- `media_type` 和严格字符编码；
- 可选的稳定业务范围标识，例如工作单元、调用或报告快照；
- 调用方声明的最大输出和覆盖影响。

来源、信任标签和用途由应用编排根据当前用例填写，不能从待处理内容中推导。`user_cli` 只表示数据从 CLI 进入，不自动表示可信：stdin diff、路径、URL 显示值和自由文本始终标记为 `untrusted_text`；只有经过 CLI schema 校验的枚举、整数和类型化动作可以标记为 `trusted_control_scalar`。

### 8.3 SecurityDecision

安全处理结果为：

| 决策 | 含义 | 是否可继续 |
| --- | --- | --- |
| `safe` | 未发现敏感内容，产物保持语义不变 | 是 |
| `redacted` | 已用受控占位符替换全部已识别敏感区间 | 是，但记录覆盖影响 |
| `blocked` | 无法在保留必要语义的前提下安全输出 | 否；可跳过该范围 |
| `indeterminate` | 扫描器、策略、编码或完整性无法得出可靠结果 | 否；安全边界失效 |

`blocked` 是策略明确拒绝某个业务范围，允许编排在如实降低覆盖后继续其他范围。`indeterminate` 表示系统无法证明安全，禁止相关数据出站或落盘，并按 `security_boundary_failed` 停止当前不可绕过路径。

### 8.4 SensitiveCategory

MVP 至少定义：

- `credential`：API Key、Token、密码和认证头；
- `private_key`：私钥材料；
- `certificate_material`：含私密内容的证书或密钥块；
- `connection_string`：带凭证的数据库、消息系统和服务连接串；
- `cloud_secret`：云访问密钥和临时凭证；
- `personal_data`：电子邮箱、电话、身份证件及项目定义的个人信息；
- `business_sensitive`：由项目固定规则识别的显式业务敏感标记内容；
- `unknown_sensitive`：高熵或结构异常、无法可靠分类但必须保护的内容。

类别只用于策略、审计和覆盖说明，不在报告中输出原始命中值。

### 8.5 SecurityFinding

扫描器返回的命中先规范化为：

- detector 标识及版本；
- 敏感类别；
- 字符区间和字节区间；
- 置信级别；
- 规则标识；
- 是否跨字段或覆盖结构边界；
- 建议动作；
- 不含原文的命中摘要。

扫描器不得返回原始命中内容到日志或错误。安全核心可以在受控内存中使用原文完成区间核对，但不会把原文放入领域结果。

### 8.6 SanitizedArtifact

安全处理成功后产生：

- 处理后的不可变 payload；
- 原始内容 SHA-256；
- 处理后内容 SHA-256；
- `SecurityDecision`；
- 命中类别和计数摘要；
- 覆盖影响；
- 实际策略和 detector manifest 摘要；
- 处理时间；
- 关联 `ArtifactDescriptor`。

该对象只在安全模块内部及持久化工作单元中存在。其他模块接收引用，不接收可修改对象。

### 8.7 PreparedSanitizedArtifact

`EvaluateArtifact` 在事务开始前预分配 `attestation_id` 和 `artifact_id`，返回不可出站、不可解析为公开 payload 的 `PreparedSanitizedArtifact`：

- 包含处理后的不可变 payload、完整证明字段和覆盖影响；
- 可以被业务变更意图以稳定 ID 引用；
- 只能暂存到所属 `PersistenceUnitOfWork`；
- 在事务提交前不具备 `SanitizedArtifactRef` 的读取或出站资格；
- 事务失败后立即失效，不能在另一事务中重放。

统一工作单元同时暂存安全证明、处理后 payload、业务记录、Trace、预算和 checkpoint。提交成功结果再把已提交的 `attestation_id` 提升为可用 `SanitizedArtifactRef`，从而避免“必须先有引用才能写业务记录，但必须先提交才能获得引用”的循环依赖。

### 8.8 SanitizedArtifactRef

公开引用至少包含：

- `attestation_id`；
- `artifact_id`；
- `task_id`；
- `source`、`kind`、`purpose`；
- `decision`；
- 处理后内容摘要；
- 策略 ID、版本和摘要；
- detector manifest 摘要；
- 创建时间和所属任务保留组；
- 可读取 payload 的受限存储引用。

`SanitizedArtifactRef` 是不透明值对象。调用方提交该引用时，持久化工作单元必须通过 `SecurityAttestationRepository` 核对：

1. `attestation_id` 存在；
2. 引用字段与权威证明完全一致；
3. payload 摘要与实际待写内容一致；
4. 证明的任务、来源、种类和用途与当前写入匹配；
5. 决策为 `safe` 或 `redacted`；
6. 策略满足任务基线和当前最低策略；
7. 证明所属任务详细数据仍在保留期内，且没有被重新绑定到另一任务、用途或内容。

同一证明允许被业务记录、Trace、checkpoint 和 provenance 多处引用，但所有引用必须指向完全相同的不可变 artifact、任务、用途和内容摘要。

系统不依赖 Python 构造器私有性提供安全性。即使调用方伪造同形对象，只要没有匹配的权威证明就不能进入事务。当前单进程和可信 SQLite 威胁模型下不额外引入 HMAC 签名或独立密钥。

安全产物存储的读取端口仅由安全模块持有。其他领域 Repository 和 Adapter 只能保存或传递不透明 ID，不能直接读取 `sanitized_artifacts`；所有 payload 读取必须经过 `ResolveArtifact` 的任务、用途、策略和摘要核对。

### 8.9 ArtifactProvenance

每个派生产物记录有序的 `derived_from_attestation_ids`。模型请求、工具结果、候选发现、结果快照和报告由哪些根输入或中间产物派生必须可追踪。

策略升级导致任一上游证明被替换、阻断或判定不兼容时，所有传递依赖的下游产物同时失效。恢复流程必须重新执行对应工作单元或降低覆盖，不能只替换根引用后继续复用旧模型响应、发现或报告。

## 9. 数据处理规则

### 9.1 原始内容生命周期

原始内容只允许存在于以下短生命周期范围：

```text
Adapter 读取
  → 受控内存缓冲
  → 安全扫描和处理
  → 创建安全证明
  → 释放原始缓冲引用
```

禁止：

- 把原始内容写入临时文件、SQLite、Trace 或异常；
- 在安全处理前使用通用对象日志、调试打印或崩溃转储；
- 在安全处理失败后保存样本供异步排查；
- 缓存未处理的平台或模型响应；
- 将原始内容附加到异常对象的公开字段。

Python 无法保证内存立即清零，因此本设计承诺“不主动持久化和传播”，不宣称抵御同账号进程内存读取、swap 或主机管理员取证。

### 9.2 结构化数据

JSON、模型响应、错误对象和报告模型按结构处理：

1. 先由 Adapter 提取项目允许的白名单字段；
2. 标量控制字段按类型校验，不能从自由文本推导；
3. 每个不可信文本字段单独扫描和脱敏；
4. 重新组装为项目内部结构；
5. 对最终序列化结果再次扫描，防止跨字段拼接形成敏感模式。

不得先把未经处理的完整第三方响应反序列化到可日志化领域对象，也不得因脱敏破坏 JSON 后再尝试容错解析。

### 9.3 Diff 的受控结构解析

为保持 unified diff 的 hunk 结构，Input Adapter 可以在禁止日志、缓存和持久化的受控内存作用域中执行纯结构解析，然后把路径和每条 diff 行的文本 payload 分别交给安全模块。该解析只能识别结构，不能执行仓库配置、hook、外部 diff 或其他代码。

Diff 脱敏必须保持：

- 文件数量和顺序；
- hunk 数量和头部；
- 每条记录的换行符数量；
- 新增、删除、上下文和元数据行类型；
- 旧行号、新行号及其映射。

多行私钥或证书按每行等数量占位符替换，不能折叠成一行。处理后重新组装并由 Input 模块再次解析核对；任一结构不变量变化时整份输入按 `input_rejected` 结束，不能生成看似完整的变更集。

路径单独处理：安全路径可持久化并用于固定版本读取；需要脱敏或阻断的路径只保存摘要和显示别名，不保存可逆 locator，也不允许后续上下文读取或跨进程重取。对应文件进入不可恢复、不可完整审查范围，结果至少为 `partial`。支持敏感路径恢复需要引入加密 locator，超出 MVP。

### 9.4 文本区间和重叠命中

- 统一以 Unicode code point 区间处理，适配器同时提供 UTF-8 字节区间用于完整性核对；
- 严格 UTF-8 解码失败不使用替换字符继续；主 diff 映射为 `input_rejected`，可隔离的单个上下文字段映射为 `blocked`，Provider 无法构造规范 UTF-8 请求映射为 `capability_incompatible`，外部响应无法可靠解码映射为 `indeterminate` 并按已知 usage 或预留规则收敛调用；
- 重叠命中先合并为最小覆盖区间；
- 类别优先级为 `private_key/credential/cloud_secret`、`connection_string`、`business_sensitive`、`personal_data`、`unknown_sensitive`；
- 任一 detector 对区间边界不确定时，结果为 `indeterminate`；
- 单产物命中数超过策略上限时不截断扫描结果，直接 `blocked`；
- 不允许仅扫描 diff 新增行，删除行和上下文行遵循相同规则。

### 9.5 脱敏占位符

占位符采用版本化格式：

```text
<REDACTED:CATEGORY:NN>
```

其中 `NN` 只在当前逻辑产物内从 1 递增。同一产物内完全相同的敏感值使用相同编号，以尽量保留引用关系；映射表仅存在于本次处理内存中，不持久化。不同产物不保证编号一致，避免形成跨任务关联标识。

占位符不包含原值哈希、长度、前后缀或 detector 细节。若原始内容本身包含合法的同形占位符，安全模块先转义为普通文本标记，避免与系统脱敏结果混淆。

### 9.6 脱敏与跳过

默认规则：

- 单行或局部 credential、个人信息和连接串能够完整定位时脱敏；
- 私钥、多行证书私密块和显式业务敏感区域按完整逻辑区块脱敏；
- 命中跨越无法安全重建的结构边界时 `blocked`；
- 敏感信息密度过高、脱敏后无法保留最小审查语义时 `blocked`；
- detector 冲突、超时、崩溃或无法证明全量扫描时 `indeterminate`。

安全模块输出结构化 `CoverageImpact`，说明受影响文件、hunk、字段或工作单元及原因。是否继续其他范围、形成 `partial` 结果或终止任务由审查编排和任务模块决定。

失败结果必须结合业务路径映射，不能只按底层错误统一处理：

| 失败位置 | 结果 |
| --- | --- |
| 主输入编码错误、损坏、超限或结构变化 | `input_rejected`，任务不进入审查 |
| 可完整隔离的文件、hunk 或上下文字段 | `blocked`，跳过范围并降低覆盖 |
| scanner 超时、崩溃、部分扫描、区间不可信或策略缺失 | `indeterminate`，按 `security_boundary_failed` 停止不可绕过路径 |
| 最终模型请求或报告无法证明完整扫描 | `indeterminate`，禁止发送或交付 |

## 10. 全路径安全门禁

### 10.1 门禁矩阵

| 路径 | 首次检查 | 最终检查 | 允许结果 |
| --- | --- | --- | --- |
| diff/仓库文本进入领域 | 字段级入站检查 | 标准化变更集序列化检查 | `safe/redacted/blocked` |
| 工具输入 | 已授权文本引用核对 | 最终工具请求检查 | `safe/redacted` |
| 工具输出进入领域 | 输出字段检查 | 统一工具结果序列化检查 | `safe/redacted/blocked` |
| 模型请求 | 各组成部分允许 `safe/redacted` | 完整序列化请求只允许 `safe` |
| 模型响应进入领域 | 响应字段检查 | 内部候选结果序列化检查 | `safe/redacted/blocked` |
| Trace/checkpoint/SQLite | payload 引用核对 | 事务提交前用途和摘要核对 | `safe/redacted` |
| 错误和 CLI 展示 | 白名单错误映射 | 最终文本检查 | `safe/redacted` |
| Markdown 报告 | 报告模型字段检查 | 最终 Markdown 字节检查 | `safe/redacted` |
| 安全日志 | 类型化字段构造 | 白名单编码器校验 | 仅安全事件结构 |

最终检查不能替代首次检查。双层门禁用于阻止安全字段在组合、模板渲染或序列化时形成新的泄漏。

### 10.2 模型出站

模型请求采用 Provider 两阶段契约：

- `prepare_request()`：把统一模型请求转换为不可变的完整供应商请求表示，包含规范化 body 字节、固定 method、规范化 origin、相对路径和协议元数据；
- `send_prepared()`：只能发送 `prepare_request()` 生成且摘要未变化的请求，不得重新序列化、补充消息内容或修改 body。

模型请求必须由 `ModelGateway` 使用已核对的安全引用组装。发送前：

1. 校验所有组成产物的任务、用途和策略；
2. 把仓库和工具内容放入明确的“不可信数据区”；
3. 使用固定系统指令声明数据不能改变工具、权限、预算和输出目标；
4. 调用 Provider 的 `prepare_request()` 取得实际待发送表示；
5. 对该表示的完整 body 字节执行扫描并核对规范化 origin；
6. 最终结果只有 `safe` 才允许继续；`redacted/blocked/indeterminate` 均废弃当前 prepared request 并拒绝调用，不在序列化字节上修改内容，也不尝试反向猜测原字段；
7. 在同一准备事务中提交 prepared request 摘要、最终请求证明、预算预留、`reserved` 调用记录、权威安全事件和脱敏 Trace；
8. 准备事务成功后执行独立的调用开始事务，原子地把调用从 `reserved` 置为 `running` 并提交对应权威安全事件；
9. 只有调用开始事务成功后才允许调用 `send_prepared()`；存在 `running` 记录而无完成事务时，恢复必须按 `unknown` 保守处理。

认证头只允许由绑定到固定规范化 origin 的 transport 在发送时追加，不能进入请求 body、Trace 或安全证明。`send_prepared()` 必须在发送前复核 method、origin、path 和 body 摘要；任何变化都按 `prepared_request_mismatch` 拒绝。Provider 不接收原始仓库对象、keyring 句柄或安全策略对象，只接收最终已授权请求。

### 10.3 模型入站

Provider 返回后：

1. Adapter 关闭通用请求/响应日志；
2. 把响应拆成白名单元数据和不可信内容；
3. 对内容字段执行安全处理；
4. 只将安全处理后的结构交给领域校验；
5. 安全处理失败时不保存原始响应；
6. 使用标准安全错误和不含原文的 Provider 请求标识收敛调用状态。

安全失败发生在供应商已处理请求之后时，预算模块仍按已知 usage 或预留规则结算，不能因响应被丢弃而忽略消耗。

### 10.4 持久化和报告

任何 SQLite 业务 payload、Trace、checkpoint 和报告内容在提交前必须携带用途匹配的证明。数据库适配器不能通过“字段看起来已脱敏”跳过核对。

报告先从安全字段组成报告模型，再渲染 Markdown，最后对完整 UTF-8 字节执行一次报告用途扫描。只有最终证明与期望报告摘要共同进入交付尝试后，Output Adapter 才能写临时文件并原子替换。

## 11. 仓库信任与能力控制

### 11.1 原则

内容和控制必须分离：

- 用户 CLI 参数、应用配置和已安装扩展声明进入控制平面；
- 仓库、平台、工具和模型文本进入数据平面；
- 数据平面内容不能转换为控制平面命令。

### 11.2 类型化许可

MVP 不实现通用权限框架，只由应用层为固定用例创建以下不可变许可：

| 许可 | 发起条件 | 固定目标 |
| --- | --- | --- |
| `FixedRepositoryReadPermit` | 已固定平台输入和显式审查工作流 | 规范化平台 origin、仓库、commit SHA 和安全路径 |
| `ModelCallPermit` | 已固定任务规格、预算预留和 prepared request 证明 | Provider、模型、origin、请求摘要和调用 ID |
| `CredentialReadPermit` | 受信任 Adapter 正在执行固定平台或模型调用 | Provider 与凭据逻辑引用 |
| `ReportWritePermit` | 当前结果快照和最终报告证明已提交 | 当前任务唯一报告目标和内容摘要 |
| `SanitizedStateWritePermit` | 统一工作单元已暂存安全证明 | 当前事务、任务和 payload 摘要 |

许可只能由对应应用用例在所有前置门禁通过后创建，不能从自由文本、模型输出、工具输出或 Adapter 返回解析。每个许可绑定单次操作和固定目标，不能转授、扩大或跨任务复用。

以下许可和能力不存在，因此任何来源都不能申请：

- `execute_repository_code`；
- `run_shell`；
- `install_dependency`；
- `load_repository_plugin`；
- `follow_repository_url`；
- `modify_budget_from_content`；
- `resume_task_from_content`；
- `publish_remote_comment`；
- `modify_repository`。

### 11.3 授权规则

- 许可类型和发起者不能从自由文本、模型输出或工具输出解析；
- 仓库内容只能作为请求 payload 的受控引用，不能作为操作、目标或许可；
- Provider、预算、规则、工具和输出目标来自固定任务规格；
- URL 主机、重定向和凭证选择由相应 Adapter 按固定配置约束；
- 模型提出调用工具、读取文件或改变策略时只作为普通候选文本，不触发动作；
- 能力拒绝记录稳定原因码，不记录诱导文本原文。

安全模块只签发和核对固定许可，实际网络、文件和凭证操作仍由对应 Adapter 执行。Adapter 必须接受对应许可才能操作，但许可不替代 Adapter 自身的 origin、路径和 transport 限制。

## 12. Prompt Injection 处理

MVP 不依赖“准确识别所有注入文本”建立安全性。防护由不可授予能力的架构保证：

1. 仓库内容始终带 `untrusted_text` 信任标签；
2. 固定系统指令与仓库数据分区组装；
3. 模型没有直接文件、网络、凭据、shell、任务或发布工具；
4. Review Tool 选择由计划和配置决定，不由模型决定；
5. 模型输出只进入候选发现，经过结构、位置、证据和安全校验；
6. 任何控制动作只接受类型化应用调用，不解析模型自然语言。

安全模块可记录固定注入特征的 `prompt_injection_indicator` 事件用于审计，但命中与否不改变上述能力边界，也不把“未命中”解释为内容可信。

## 13. 安全策略版本与恢复

### 13.1 任务基线

任务创建时固定 `policy_id`、`policy_version` 和 `policy_digest` 作为最低安全基线。每个安全证明记录实际使用策略。

### 13.2 非降级比较

策略兼容不是简单比较版本号。新策略只有同时满足以下条件才视为不弱于基线：

- 策略 schema 可由当前应用完整理解；
- 敏感类别集合是基线的超集；
- detector 能力覆盖不减少；
- 对相同来源和用途的动作相同或更严格；
- 不新增仓库可控 allowlist、过滤器或绕过条件；
- 规模、超时和不确定结果处理不会把原 `blocked/indeterminate` 放宽为允许；
- 占位符格式变化不会恢复或泄漏原值；
- 能力授权集合没有扩大。

无法证明非降级时返回 `security_policy_incompatible`，原任务不得恢复。

### 13.3 旧产物复用

- 策略和 detector manifest 完全一致且证明有效时直接复用；
- 新策略只改变与该产物无关的用途时，可通过兼容性证明复用；
- 新增 detector、敏感类别或更严格动作可能影响该产物时必须重新扫描；
- 原始内容仍可从固定只读来源重新获取时，重新获取后处理并生成新证明；
- 原始内容不可重新获取且旧安全 payload 不能证明满足新策略时，相关范围 `blocked`，任务暂停或形成部分结果；
- 任一上游证明发生变化时，沿 `derived_from_attestation_ids` 使工具结果、模型请求、模型响应、候选发现、结果快照和报告传递失效；
- 传递失效后的工作单元必须重新执行并产生新尝试；无法重新执行时降低覆盖，不能把旧派生结果标记为已重新验证；
- 不允许为了恢复而重新启用已撤销的旧弱策略。

## 14. 扫描适配器契约

### 14.1 SensitiveDataScannerPort

输入：

- 原始只读内容；
- `ArtifactDescriptor`；
- 固定 detector manifest；
- 处理时限和规模上限。

输出：

- 完整扫描成功标记；
- 结构化 `SecurityFinding` 集合；
- 实际 detector 名称、版本和配置摘要；
- 扫描覆盖范围；
- 受控性能统计；
- 标准错误码。

### 14.2 适配器约束

- 关闭联网验证；
- 不读取目标仓库 baseline、allowlist、插件、过滤器或配置；
- 不跟随文件路径读取额外内容；
- 不执行 hook、shell、动态导入或回调；
- detector 集合和配置由应用随版本固定；
- 返回顺序不影响最终结果；
- 超时、崩溃、部分扫描或未知 detector 一律 `indeterminate`；
- 第三方异常转换为白名单错误，不携带原始内容；
- 对同一内容、策略和版本必须产生确定性结果。

detect-secrets 位于该端口之后。项目自有 PII、连接串、证书和业务敏感规则作为同一 manifest 中的固定 detector 接入。

## 15. 应用用例

### 15.1 EvaluateArtifact

输入：原始内容、`ArtifactDescriptor`、当前策略引用。

行为：

1. 校验来源、种类、用途、编码和规模；
2. 调用固定扫描器集合；
3. 规范化和核对命中；
4. 根据策略产生 `safe/redacted/blocked/indeterminate`；
5. 对允许结果计算摘要并预分配 `attestation_id/artifact_id`；
6. 返回 `PreparedSanitizedArtifact` 和覆盖影响。

`PreparedSanitizedArtifact` 可被同一工作单元中的业务记录引用，但安全证明提交成功前不能被解析为公开 payload，也不能被视为可出站。

### 15.2 StageAttestation

输入：`PreparedSanitizedArtifact` 和所属持久化工作单元。

行为：把证明和处理后 payload 暂存到统一工作单元，业务记录使用预分配的稳定 ID 建立引用。统一提交成功结果返回对应 `SanitizedArtifactRef`；事务失败时 prepared 对象失效，不返回可用引用。

模型请求的最终出站证明必须与预算预留、调用记录和请求 Trace 同事务提交。

### 15.3 ResolveArtifact

输入：`SanitizedArtifactRef`、期望任务、来源、种类、用途和最低策略。

行为：核对权威证明并返回只读 payload。用途不匹配、摘要错误、所属任务详细数据已清理、策略不兼容或决策不允许时拒绝。

默认不允许任意用途复用。仅明确列入策略的安全用途转换可以基于同一处理后内容创建新证明，例如已安全的领域文本再次经过最终模型请求扫描。

### 15.4 AssessRevalidation

输入：旧引用、当前策略和 provenance 摘要。

行为：纯粹判断并返回：

- `reuse`：旧证明可直接复用；
- `reprocess_required`：必须从固定来源重新取得原内容并重新处理；
- `block`：来源不可重取或旧产物无法满足新策略。

安全模块不发起平台或文件读取。需要重取时，由审查编排模块签发 `FixedRepositoryReadPermit`，通过 Input Provider 读取已固定版本，再把原始结果直接送入 `EvaluateArtifact`。外部读取的尝试状态、Trace、checkpoint、失败和 unknown 语义由输入及编排模块负责。

### 15.5 AuthorizeCapability

输入：具体类型的许可申请和固定任务规格摘要。

行为：验证许可类型、发起用例、目标、任务固定条件和前置门禁。返回单次固定许可或稳定拒绝码，不执行实际操作。

### 15.6 EmitSecurityEvent

输入：类型化安全事件。

行为：使用白名单编码器生成不含自由原文的事件意图。任务关联的权威事件必须暂存到对应 `PersistenceUnitOfWork`，提交后才成为安全事实；`SecurityLogPort` 只投影已提交事件用于本地展示或日志文件，不是权威存储。如果投影失败，不允许把原始 payload 作为降级日志输出，也不回滚已经一致提交的业务状态。

## 16. 安全事件与审计

### 16.1 事件字段

安全事件只允许包含：

- `event_id`、`event_type`、`occurred_at`；
- 可选 `task_id`、阶段、工作单元或调用标识；
- 策略和 detector manifest 摘要；
- 来源、种类、用途；
- 决策和稳定原因码；
- 命中类别及数量；
- 处理前后内容摘要；
- 覆盖影响摘要；
- Adapter、Provider 或工具的固定标识和版本；
- 不含用户文本的恢复建议枚举。

禁止包含命中原文、上下文片段、prompt、模型回复、URL query、认证头、环境变量值、堆栈和第三方错误原文。

### 16.2 防递归泄漏

安全日志不接收任意消息字符串。事件描述由稳定 `event_type/reason_code` 在展示端映射，标识字段采用严格格式和长度限制。这样即使主扫描器不可用，也能记录 `scanner_unavailable` 等常量事件，而不需要再次扫描不可信原文。

### 16.3 保留

任务关联安全证明和安全事件加入任务统一保留组。未终止期间，只要任务详细数据仍存在，早期证明持续有效，不按创建时 checkpoint 单独过期；任务终止后统一使用任务的 `retention_expires_at`。任务清理时在同一事务中删除详细安全记录，只在墓碑保留最终安全状态和策略摘要，不保留命中类别明细。

与任务无关的凭据配置失败等安全运维事件由基础设施设计确定本地保留策略，但仍必须使用相同白名单事件结构。

### 16.4 权威事件与事务边界

SQLite `security_events` 是任务关联安全事件的权威事实源：

- 模型发送许可、prepared request 安全通过等发送前事件加入调用准备事务；
- 模型响应处理、安全拒绝和 usage 相关事件加入调用完成事务；
- 工具、checkpoint、结果快照和报告事件加入各自业务事务；
- 事务失败时对应事件与业务状态共同不存在，不能留下孤立“已允许”或“已完成”事件；
- `SecurityLogPort` 只从已提交事件生成投影，投影失败可重试，但不得改变任务、预算、调用和安全证明状态；
- 数据库无法提交权威安全事件时按持久化完整性错误停止，不以文件日志代替。

## 17. 错误模型与失败语义

公开安全错误至少包含：

- 稳定 `code`；
- 阶段、来源、种类和用途；
- 影响范围；
- `recoverable`；
- 覆盖影响；
- 安全处理后的关联标识；
- 固定下一步枚举。

主要错误码：

- `security_policy_missing`；
- `security_policy_invalid`；
- `security_policy_incompatible`；
- `scanner_unavailable`；
- `scanner_timeout`；
- `scanner_incomplete`；
- `unsupported_encoding`；
- `artifact_too_large`；
- `finding_range_invalid`；
- `sensitive_content_blocked`；
- `sanitization_indeterminate`；
- `attestation_missing`；
- `attestation_mismatch`；
- `attestation_expired`；
- `artifact_purpose_mismatch`；
- `prepared_request_mismatch`；
- `capability_denied`；
- `untrusted_control_input`；
- `security_log_failed`。

失败收敛：

- 明确 `blocked` 且范围可隔离：跳过该范围，降低覆盖；
- 出站最终检查失败：不创建外部请求；
- 入站处理失败：不保存原始响应，调用按已知 usage 收敛；
- 证明或策略核对失败：拒绝事务；
- 扫描器或策略整体不可用：`security_boundary_failed`，停止新的外部调用和相关持久化；
- 权威安全事件提交失败：与所属业务事务共同失败，并按持久化完整性错误停止；
- `SecurityLogPort` 投影失败：记录可重试的脱敏投影错误，不回滚已经一致提交的业务状态，也不输出原始诊断。

## 18. 持久化逻辑结构

SQLite 适配器至少支持以下逻辑集合，物理表结构由基础设施模块确定：

| 集合 | 写入模式 | 关键约束 |
| --- | --- | --- |
| `security_policies` | 随应用版本注册，只读 | `(policy_id, version)` 唯一，摘要不可变 |
| `security_attestations` | 只追加 | `attestation_id` 唯一，绑定任务、用途、摘要和策略 |
| `sanitized_artifacts` | 只追加或内容寻址 | 只能保存 `safe/redacted` payload，摘要必须匹配 |
| `artifact_provenance` | 只追加 | 记录派生产物到上游证明的有向无环关系 |
| `security_events` | 只追加 | 仅白名单字段，不接受自由原文 |
| `policy_compatibility` | 只追加 | 明确记录策略间兼容判断和依据摘要 |

业务模块保存 payload 时，安全证明、业务记录、Trace、预算和 checkpoint 必须能加入同一 `PersistenceUnitOfWork`。外键和唯一约束必须防止孤立证明、跨任务引用和一份证明绑定不同内容。

安全模块不单独提交跨模块事务。

`sanitized_artifacts` 的读取能力不得暴露给其他领域 Repository、Adapter 或通用查询端口。`PersistenceUnitOfWork` 可以暂存和写入该集合，但不能向调用方直接返回 payload。

## 19. 端口

安全核心依赖：

- `SensitiveDataScannerPort`：执行固定、离线、确定性的敏感数据扫描；
- `SecurityAttestationRepository`：仅供安全模块读取权威安全证明、payload、provenance 和策略兼容记录；
- `PersistenceUnitOfWork`：原子提交证明、业务状态、Trace 和 checkpoint；
- `SecurityLogPort`：只读取并投影 SQLite 已提交的结构化白名单安全事件，不创建权威事实；
- `Clock`：提供可测试 UTC 时间；
- `IdGenerator`：生成不可预测标识；
- `ContentHasher`：生成规范化 SHA-256 摘要。

安全模块不依赖 SQLite、keyring、Typer、Rich、LangChain、PyGithub、python-gitlab、HTTPX、Jinja2 或 detect-secrets 的具体类型。

## 20. 与其他模块的契约

### 20.1 任务管理模块

- `TaskSpec` 固定安全策略基线；
- `TaskTransitionIntent` 只能引用已提交或同事务待提交的安全证明；
- checkpoint、结果快照、交付尝试和错误摘要必须核对用途匹配；
- `security_boundary_failed` 按不可恢复原因收敛；
- 任务清理同时删除详细安全证明和安全事件。

### 20.2 输入模块

- 原始平台响应和 diff 在标准化前先完成字段级安全处理；
- 路径规范化、完整性和固定版本仍由输入模块负责；
- Diff 可先在受控内存中做纯结构解析，但脱敏前后必须保持 hunk 和行号映射；
- 敏感路径不保存可逆 locator，不允许恢复后重新读取对应文件；
- 被阻断范围必须进入覆盖模型；
- 输入模块不能读取仓库安全配置来改变策略。

### 20.3 预算与模型网关

- 最终模型请求证明与预算预留、调用记录和请求 Trace 同事务提交；
- Model Provider 必须实现 `prepare_request()/send_prepared()`，线上发送 body 与被扫描、计数和记录摘要的 body 完全一致；
- 安全允许不代表预算允许，两个门禁必须都通过；
- 模型响应安全失败不免除实际 usage 结算；
- Provider 只能收到最终已授权请求。

### 20.4 Trace 模块

- Trace 只接收 `SanitizedArtifactRef` 或白名单安全事件；
- Trace 不保存扫描命中原文；
- 每个模型、工具和报告事件记录实际策略摘要；
- 安全证明与关联 Trace 使用同一生命周期；
- Trace 和其他派生产物记录 `derived_from_attestation_ids`，用于策略升级后的传递失效。

### 20.5 Review Tool

- 工具只接收用途为 `tool_ingress` 的已授权文本；
- 工具结果按 `tool_output` 来源重新执行入站安全处理；
- 工具规则不能修改安全策略、detector 或能力；
- 工具越权与资源超限使用稳定安全事件记录。

### 20.6 报告与 Output Adapter

- 报告模块只读取安全字段；
- 完整 Markdown 必须通过最终 `report_delivery` 检查；
- Output Adapter 只写与当前任务和快照匹配的固定目标；
- 远程回评不属于当前安全能力集合。

### 20.7 凭据适配

- 安全模块只接触凭据逻辑引用和固定 Provider 身份，不读取凭据值；
- 凭据值从 keyring 或显式环境注入直接交给对应受信任 Adapter；
- 认证头、凭据值和环境变量值不能进入领域对象、错误或安全事件；
- 缺少安全 keyring backend 时交互式设置失败，不回退明文文件。

## 21. 关键不变量

实现和测试必须持续证明：

1. 未经安全处理的 payload 不能模型出站、跨模块持久化或报告落盘；
2. 每个可用安全引用都对应唯一、已提交且可核对的权威证明；
3. 同一证明不能绑定不同任务、用途或内容摘要；
4. `blocked/indeterminate` 结果不能被调用方提升为允许；
5. 原始内容不会进入 SQLite、Trace、checkpoint、日志、错误和报告；
6. 删除行、上下文行、工具结果、模型响应和异常与新增行使用同一安全标准；
7. Provider 实际发送的 body 与最终扫描、Token 预留和 Trace 对应的 prepared request body 完全一致，Markdown 报告也会再次扫描；
8. 扫描器不可用、超时或部分扫描时失败关闭；
9. 目标仓库不能提供 detector、allowlist、插件、过滤器或安全配置；
10. 仓库和模型文本不能触发 shell、网络、凭据、预算、恢复、清理或发布动作；
11. 策略恢复兼容性按能力比较，不按版本号大小猜测；
12. 弱于任务基线的策略不能用于恢复或创建新安全证明；
13. 模型响应被安全拒绝时仍按预算规则结算；
14. 安全日志只包含白名单结构，不接收任意原文；
15. 安全证明、业务记录和关联 Trace/checkpoint 的提交全有或全无；
16. 清理详细任务数据时同步清理关联安全证明，墓碑不保留敏感命中明细；
17. `safe` 只表示未命中当前固定策略，不表示内容可信或可授予能力；
18. Diff 安全处理前后文件、hunk、行类型和旧新行号映射不变；
19. 任务详细数据保留期间，早期已完成单元的安全证明不会独立过期；
20. 上游证明失效会沿 provenance 关系使所有派生结果失效。

## 22. 测试设计

### 22.1 领域单元测试

- 覆盖四种 `SecurityDecision` 和所有动作矩阵分支；
- 验证重叠区间合并、类别优先级和占位符编号；
- 验证同一产物内一致替换、跨产物不形成关联；
- 验证合法占位符文本被转义；
- 验证严格 UTF-8、大小和命中数边界；
- 验证策略非降级比较和不可比较策略拒绝；
- 验证五类固定许可的允许、拒绝、目标绑定和不可信发起者；
- 使用 Hypothesis 生成命中区间，证明输出不含任一原命中子串。

### 22.2 扫描适配器合约测试

- 固定 detector manifest 产生确定性结果；
- 禁止联网、仓库 baseline、allowlist、插件和过滤器；
- scanner 超时、崩溃、部分覆盖和未知 detector 均返回 `indeterminate`；
- 异常不包含输入原文；
- 多行私钥、连接串、API Key、PII、证书和业务标记均有固定样例；
- 删除行、上下文行和模型回显使用相同 detector。

### 22.3 安全证明与持久化测试

- 伪造、缺失、任务已清理和字段不匹配的引用被拒绝；
- 内容摘要、任务、来源、种类或用途变化被拒绝；
- 同一证明可以被业务记录、Trace、checkpoint 和 provenance 合法多引用，但不能重新绑定不同 payload、任务或用途；
- 证明与业务事务共同成功或共同回滚；
- 安全证明提交失败时不返回可出站引用；
- prepared 对象可以在同一事务中被业务记录引用，但不能在提交前读取或出站；
- 长任务和多次 checkpoint 不会使早期证明独立过期；
- 策略升级使根证明变化时，派生结果按 provenance 全部失效；
- 清理任务不会留下可解析的孤立安全 payload。

### 22.4 全路径泄漏测试

向以下位置分别注入唯一模拟 secret：

- diff 新增、删除和上下文；
- 文件路径和按需上下文；
- 工具输入和输出；
- prompt 模板变量；
- 模型正常响应、无效结构响应和错误；
- 第三方 SDK 异常；
- Trace、checkpoint 和预算关联字段；
- CLI 错误；
- Markdown 模板和最终报告。

测试同时检查实际 Provider 请求、SQLite 文件、报告文件、临时文件、日志捕获和异常对象，证明模拟 secret 不存在。

模型 Provider 合约测试必须截获 transport 实际发送的 method、origin、path 和 body 字节，证明它们与 `prepare_request()` 的表示及安全证明摘要一致；LangChain 或供应商 Adapter 不得在安全检查后重新序列化消息 body。最终扫描结果不是 `safe` 时，测试必须证明原 prepared request 被废弃且没有发送。

### 22.5 Prompt Injection 与能力测试

- 仓库要求读取环境变量、调用网络、执行 shell、修改预算、恢复任务或发布评论时均无对应动作；
- 模型输出伪造固定许可、工具调用或任务命令时只作为普通无效数据；
- 恶意规则包声明 Python 回调、路径、URL 或动态导入时在 Tool Registry 边界拒绝；
- Provider 和 Output Adapter 不能通过仓库内容改变目标；
- 未命中注入 detector 的文本仍保持 `untrusted_text` 标签。

### 22.6 故障注入

在扫描开始、扫描完成、脱敏、证明创建、证明提交、prepared request 废弃、调用准备事务、调用开始事务、模型发送、响应处理、权威安全事件提交、安全日志投影、报告渲染和最终文件替换边界注入中断。

验证：

- 原始内容没有落盘；
- 未提交证明不能恢复为成功；
- 准备事务后中断时调用保持 `reserved` 且不会发送；
- `running` 提交后、发送前中断以及发送后、完成事务前中断均恢复为 `unknown`；
- 外部调用已发生时调用状态和预算如实收敛；
- 安全边界不确定时不继续新的外部调用；
- 权威安全事件与业务事务共同提交或回滚，日志投影失败不会回滚业务状态或触发原文降级输出；
- 脱敏多行 secret 后 diff 的 hunk 数量、换行和旧新行号映射不变；
- 敏感路径在进程重启后不会被恢复读取，并明确降低覆盖；
- 策略升级后的派生结果不会被错误复用。

## 23. 问题与裁决记录

### 23.1 安全证明是否使用 HMAC

问题：任务模块要求 `SanitizedArtifactRef` 不可伪造。

裁决：MVP 使用“权威证明记录 + 事务核对 + 不透明引用”，不使用 HMAC。当前威胁模型信任同一 OS 账号和 SQLite 完整性；HMAC 需要新增密钥生命周期、恢复和轮换问题，却不能防御已控制同账号进程或数据库的攻击者。未来引入跨进程、不可信插件或远程存储时重新评估签名。

### 23.2 是否保存原始内容哈希

问题：原始内容哈希有助于重验证和幂等，但可能形成关联信息。

裁决：保存无盐 SHA-256 仅用于高熵或代码类完整内容，不为短凭据命中单独计算或暴露哈希。原始内容摘要只存在安全证明内部，不进入普通报告和 CLI。当前任务模块需要内容完整性核对，收益高于有限的同账号关联风险。

### 23.3 是否跨产物稳定替换同一 secret

问题：稳定替换有助于模型理解引用关系，但会形成跨文件和跨任务关联。

裁决：仅在单个逻辑产物内稳定编号，映射不持久化；跨产物不稳定。需要跨文件语义时由上层先组成一个受限逻辑产物，再整体扫描。

### 23.4 Prompt Injection 是否作为敏感内容删除

问题：删除所有指令式文本会破坏代码审查语义，且无法可靠识别全部注入。

裁决：不以注入检测作为主要安全边界。仓库文本保留为不可信数据，能力由架构隔离；固定特征只用于审计和风险提示。

### 23.5 扫描器失败能否降级

问题：局部扫描器失败时继续可以提高可用性。

裁决：固定 manifest 中任一必需 detector 未完整执行即 `indeterminate`，禁止相关数据出站或落盘。只有策略明确标为可选且不影响该来源/用途覆盖的 detector 才能跳过；MVP 默认 detector 均为必需。

### 23.6 安全日志失败如何处理

问题：把所有日志失败都升级为任务失败会降低可用性，但忽略失败会失去审计。

裁决：SQLite `security_events` 是权威事实，必须与模型准备、模型完成、工具、checkpoint 或报告等所属业务状态在同一事务提交；提交失败时业务状态共同失败。`SecurityLogPort` 只是已提交事件的展示或文件投影，投影失败可重试，但不回滚一致业务状态，也不允许降级输出原文。

### 23.7 OpenAI-compatible `base_url`

问题：自定义端点可能造成 SSRF、凭据误投和数据地域问题。

裁决：安全核心固定最低准入要求，Model Provider 与配置模块负责实现：

- 端点只能来自本机显式配置，不能来自仓库、平台内容或模型响应；
- URL 规范化后固定到任务规格，禁止 userinfo、fragment 和非预期 query；
- 默认只允许 HTTPS，重定向关闭；
- 凭据绑定规范化 origin，不能向其他 origin 发送；
- 连接前解析地址，连接后核对实际对端；DNS 结果变化后必须重新校验；
- 默认拒绝 loopback、link-local、私网、保留地址和 Unix socket；
- 只有用户在本机配置中显式启用 `local_endpoint` 模式时才允许 loopback 或私网，并使用独立凭据引用；该模式仍禁止重定向和跨 origin；
- 自定义端点完成上述校验前不得注册为硬预算安全模式下的可用 Provider。

### 23.8 多 OS 用户共享凭据

问题：早期描述可能被理解为多个本机用户共享凭据，但 keyring 是账号级。

裁决：MVP 明确为同一可信 OS 账号，不支持跨账号共享。未来多用户运行必须重新设计身份、授权、加密和审计。

### 23.9 报告长期保留

问题：任务清理不删除 Markdown 报告，报告可能在七天后继续存在。

裁决：安全模块要求报告始终为最终扫描后的脱敏产物，但不决定删除期限。报告生命周期由后续报告/输出管理设计记录；在其完成前，不能宣称七天后所有审查数据均被删除。

### 23.10 证明与业务事务提交顺序

问题：业务记录需要引用安全证明，但未提交的证明不能作为可用引用。

裁决：`EvaluateArtifact` 预分配稳定 ID 并返回不可出站的 `PreparedSanitizedArtifact`。统一工作单元同时暂存证明和引用该 ID 的业务记录，提交成功后才提升为 `SanitizedArtifactRef`。失败事务中的 prepared 对象永久失效。

### 23.11 实际模型请求的一致性

问题：LangChain 或 Provider 可能在安全扫描后重新序列化或补充请求 body。

裁决：Provider 使用 `prepare_request()/send_prepared()` 两阶段契约。扫描、Token 预留、Trace 和实际发送必须针对同一不可变 body 字节；transport 只能为固定 origin 追加认证头。

### 23.12 Diff 脱敏与行号

问题：多行 secret 替换可能破坏 unified diff 的 hunk 计数和评论定位。

裁决：允许在受控内存中先做纯结构解析，按行处理内容；脱敏保持换行数和行类型，重组后再次解析核对。结构变化则拒绝整份输入。

### 23.13 敏感路径恢复

问题：不保存原始敏感路径时，进程重启后无法按固定版本重新读取文件。

裁决：MVP 不保存加密 locator。需要脱敏或阻断的路径不再允许上下文读取和跨进程恢复，对应文件明确进入部分覆盖。

### 23.14 策略升级的传递失效

问题：只重扫根输入不能证明旧模型响应、发现和报告仍可复用。

裁决：所有派生产物记录 `derived_from_attestation_ids`。上游证明变化时沿 provenance 使下游结果失效，重新执行工作单元或降低覆盖。

### 23.15 最终请求扫描产生脱敏

问题：字节级最终扫描若直接修改 prepared request，会使安全证明与 Provider 实际发送对象不一致。

裁决：最终 prepared request 只接受 `safe`。`redacted/blocked/indeterminate` 均废弃该对象并拒绝调用，不对序列化字节做脱敏，也不尝试把字节区间反向映射到原字段。字段级安全处理必须在 prepare 之前完成。

### 23.16 重验证读取职责

问题：安全模块直接读取固定仓库来源会穿透输入模块和编排边界，并引入未建模的外部调用状态。

裁决：安全模块只通过 `AssessRevalidation` 返回复用、重处理或阻断决策。编排模块负责签发读取许可并调用 Input Provider，安全模块不依赖远程或文件读取端口。

### 23.17 安全事件权威来源

问题：文件日志和 SQLite 事件若都被视为权威，会产生调用状态与安全审计不一致。

裁决：SQLite `security_events` 是权威事实并进入所属业务事务；`SecurityLogPort` 只投影已提交事件。投影失败不改写已经一致提交的状态。

### 23.18 模型调用开始标记

问题：准备事务提交后直接发送会在崩溃时留下 `reserved` 状态，恢复可能错误释放预算并重试。

裁决：准备事务后增加独立调用开始事务，原子写入 `running` 和权威安全事件。只有该事务成功后才能发送；任何 `running` 且无完成事务的调用恢复为 `unknown`。

## 24. ADR

### ADR-S-001：使用持久化安全证明而非标记字符串

- 状态：接受
- 决策：跨模块和持久化边界使用 `SanitizedArtifactRef`，并在统一工作单元核对权威证明。
- 原因：普通字符串或布尔标记不能证明处理过程，也不能防止遗漏和伪造。
- 代价：增加证明存储、用途管理和事务核对。

### ADR-S-002：安全失败默认关闭

- 状态：接受
- 决策：扫描器、策略、编码或证明不确定时禁止出站和落盘。
- 原因：FR-025～028 是 P0 门禁，错误放行的代价高于局部不可用。
- 代价：扫描基础设施异常会暂停或终止任务。

### ADR-S-003：以能力隔离防御 Prompt Injection

- 状态：接受
- 决策：仓库和模型内容不获得控制能力，注入检测仅作辅助审计。
- 原因：自然语言注入无法完备识别，能力隔离可以提供确定性保证。
- 代价：不能宣称检测出所有恶意指令，但能够证明其无法直接触发系统动作。

### ADR-S-004：MVP 不引入独立安全进程和数据库加密

- 状态：接受
- 决策：扫描在受信任单进程内执行，SQLite 只保存安全产物并依赖 OS 账号权限。
- 原因：符合已确认威胁模型和 MVP 范围。
- 代价：不防御同账号恶意进程、主机管理员、内存取证和磁盘离线攻击。

## 25. 后续模块必须遵守的契约

- 预算模块必须允许最终模型请求安全证明与预算预留同事务提交；
- Trace 模块只能保存安全引用或白名单事件；
- 输入模块必须在领域标准化前完成外部文本入站处理；
- 审查规划模块必须传播被阻断范围的覆盖影响；
- 审查执行模块必须通过 ModelGateway 和 Tool Gateway 使用用途匹配的安全引用；
- 发现处理模块必须重新检查模型和工具产生的候选文本；
- 报告模块必须对完整 Markdown 做最终检查；
- 编排模块必须区分 `blocked` 与 `indeterminate` 的降级和终止语义；
- Model Provider 必须设计自定义 `base_url` 的 SSRF、重定向和凭据绑定约束；
- Tool Registry 和受限运行时不得加载仓库代码、路径、URL 或动态回调；
- SQLite 适配器必须实现安全证明与业务状态的原子核对和提交；
- CLI 和凭据适配器不得把凭据、环境变量或第三方异常原文写入显示和日志。

后续模块若无法满足以上契约，必须先修订本设计并在“问题与裁决记录”中说明影响，不能通过 Adapter 特例绕过。

## 26. 设计结论

安全模块以版本化策略统一管理敏感数据识别、脱敏、阻断、能力授权和审计边界，以持久化权威证明保证安全处理不可由调用方伪造。所有模型出站、外部入站、跨模块持久化和报告交付都执行用途匹配的双层门禁；仓库和模型内容始终处于数据平面，不能取得系统控制能力。

该设计满足本地 CLI MVP 的 Secret 保护、凭据隔离、禁止执行仓库代码和 prompt injection 防护要求，并为预算、Trace、输入、执行和报告模块提供可验证的安全契约。
