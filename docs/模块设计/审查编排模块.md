# Code Review Agent 审查编排模块详细设计

## 1. 文档状态

- 日期：2026-09-10
- 状态：设计完成，待复审
- 上游依据：《架构设计.md》及任务、安全、预算、Trace、输入、规划、执行、发现处理、报告模块设计
- 适用范围：本地 CLI、单进程、串行工作单元、单任务单执行者

## 2. 设计结论

编排模块采用“显式阶段机 + 执行会话 + 领域 Intent + 统一持久化工作单元”。它拥有流程顺序、停止边界和错误传播，不拥有输入、预算、安全、发现或报告业务规则，也不直接更新 `Task`。

```text
创建/加载任务 → 取得审查租约 → 恢复核对
→ 输入获取与标准化 → 冻结计划 → 串行执行
→ 发现确定性收敛 → ResultSnapshot → 释放审查租约
→ 取得报告租约 → 报告生成与交付 → 关闭会话
```

外部 I/O 发出前先提交 `running`；已发出但无法确认结果时统一收敛为 `unknown`，不得自动重试。暂停、终止、预算停止和 unknown 均先停止新外部调用，再用已有安全事实完成发现收敛。

## 3. 职责边界

编排负责创建/恢复 `ExecutionSession`、选择下一阶段、串行调度、检查租约和停止请求、聚合领域结果与 Intent、选择继续/降级/暂停/终止、组织快照和报告交付。

编排不解析 diff、不签发安全证明、不切分计划、不运行工具或直接调用模型、不验证发现、不计算预算、不构造 Trace payload、不判定任务迁移、不渲染 Markdown，也不访问 SQLite、SDK、keyring 或文件系统。任务管理模块仍是任务状态唯一写入者。

## 4. ExecutionSession 与阶段机

`ExecutionSession` 包含 session/task ID、`mode`、lease ID/purpose、fencing token、预期任务版本、起始/当前阶段、当前 work unit/execution、停止请求、最近安全边界和关闭原因。它只记录编排事实，不是任务、预算或 checkpoint 的第二事实源；`session.phase` 与 `Task.phase`、`Task.delivery_state` 是不同轴，不要求逐值对应。

| 阶段 | 成功产物 | 下一阶段 |
| --- | --- | --- |
| `session_acquired` | ExecutionSession | `reconciling` 或 `input_acquiring` |
| `reconciling` | 未完成尝试的确定状态或 unknown | 对应未完成阶段 |
| `input_acquiring` | 已安全处理的固定输入 | `input_normalizing` |
| `input_normalizing` | ChangeSet、InputBinding | `planning` |
| `planning` | 冻结 ReviewPlan | `executing` |
| `executing` | WorkUnitExecutionResult、CandidateFinding | 下一单元或 `consolidating` |
| `consolidating` | FindingSet、CoverageSnapshot、TraceLink | `snapshotting` |
| `snapshotting` | ResultSnapshot | `review_closed` |
| `review_closed` | 审查租约已释放 | `report_acquiring` |
| `report_acquiring` | 报告租约、DeliveryAttempt | `reporting` |
| `reporting` | 报告产物或标准交付错误 | `completed` |

阶段只能单调前进。恢复从最近有效 checkpoint 的下一动作继续。阶段与任务控制、审查结果、报告交付、模型双轴状态和预算账户状态正交：`completed` 只表示本次编排会话已经结束（无论报告交付是 `succeeded/failed/unknown`），任务模块的权威 `Task.delivery_state` 仍独立取 `not_ready/pending/succeeded/failed/unknown` 五态，编排结束不改写该状态。

## 5. 主流程与收敛

只有完整性已证明、版本固定且安全证明有效的 InputBinding 才能进入规划。计划冻结后按 `execution_rank` 串行执行；编排不能调整范围、工具、模型或输出 schema。显式重试创建新的 execution、attempt、reservation 和 Trace。

全部单元完成、预算不足/超额、模型 unknown、用户暂停/终止、可降级失败时均进入确定性收敛。收敛不得读取新上下文、运行工具、调用模型或追加预算。FindingSet、CoverageSnapshot、FinalFinding、逐发现 TraceLink 和 checkpoint 提交后，任务模块才能创建 ResultSnapshot。

ResultSnapshot 固定 InputBinding、计划、覆盖、FindingSet、BudgetSummary、UnknownAttemptSet、TraceSummary 及版本、摘要和安全证明。报告只读取确切快照；报告失败或 unknown 仅改变交付状态。

发现处理模块的收敛请求以 `execution_fact_boundary_id`（即对应 `findings_consolidated` checkpoint 的 `checkpoint_id`）锚定所依据的执行事实边界；编排在收敛后提交该 checkpoint 时即产出该边界标识，任务与基础设施 schema 均以 `checkpoint_id` 引用同一对象（见发现处理模块 §3.3/§11）。

## 6. 租约、暂停、恢复与终止

`review_execution` 允许输入、规划、执行、收敛和快照；`report_delivery` 只允许报告构建、写入和核对。两者互斥。同一任务最多一个有效租约，默认时长 120 秒、续约间隔 30 秒；心跳不更新业务版本或恢复期限。

阶段开始、外部 I/O 前后、工具/工作单元前后、收敛、快照和报告替换前必须核对租约。续约失败后禁止新外部 I/O，未提交本地结果丢弃，旧 fencing 写入由 UoW 拒绝。

安全停止边界是完整事务、外部结果已确定/unknown、工具或工作单元 checkpoint、FindingSet、ResultSnapshot、报告替换核对完成之后。

暂停和终止均为协作式请求，不强杀、不取消事务、不篡改已发生事实。已有候选先收敛，再提交 partial/unknown 快照、控制状态、原因、Trace、checkpoint 和租约释放。终止后报告仍可独立交付。

恢复必须显式触发，校验保留期、固定输入、计划、Provider、模型、规则、工具、安全、预算和租约。无完成事务的 running 外部尝试转 unknown；已完成 checkpoint 复用；新尝试使用新 ID 和预留。固定语义变化时必须新建任务。

## 7. unknown 与错误传播

| 外部 I/O | unknown 条件 | 恢复 |
| --- | --- | --- |
| 平台读取 | 响应未完整安全持久化 | 不拼接旧响应，重新完整获取 |
| 模型调用 | running 后缺少完成事务 | 预留转不确定消耗，确认后新尝试 |
| 报告写入 | 替换可能成功但 DB 未确认 | 先核对文件身份和摘要 |

本地确定性工具中断使用 `interrupted` 或 `failed_known`。

| 分类 | 决定 | 结果影响 |
| --- | --- | --- |
| 输入拒绝/不完整/漂移 | 终止，不调用模型 | 无快照（结果派生 pending、交付 not_ready）；计划已冻结时创建 failed 快照 |
| 缺凭证、明确临时失败 | 暂停 | 保留事实 |
| 固定能力不兼容 | 终止，要求新任务 | 无快照（结果派生 pending、交付 not_ready）；计划已冻结时创建 failed 快照 |
| 模型 unknown | 停止新调用并收敛 | unknown |
| 可选工具失败、安全跳过 | 继续其他范围 | 证据降级（范围仍完整，结果仍 complete_with_findings/complete_no_findings）或覆盖降级（产生 partial 快照），按实际覆盖判定 |
| 安全或持久化失效 | 立即停止 | 不声称可靠成功 |
| 预算不足/超额 | 收敛并暂停/冻结 | partial |
| 报告失败/unknown | 失败或先核对 | 审查结果不变 |

只有能如实说明 reviewed、unreviewed、unreviewable 和 unknown 范围时才允许降级。

## 8. 原子边界与公开服务

UoW 覆盖任务创建、租约取得、输入获取/绑定、计划冻结、工具开始/完成、模型准备/开始/完成/unknown、预算超额第一阶段、发现收敛、快照、报告开始/完成、暂停/终止和清理。模型准备原子提交安全请求证明、预算预留、reserved 调用、请求 Trace 和工作单元关系；模型完成原子提交安全响应/错误、usage、双轴状态、候选、checkpoint 和 Trace。禁止事后补写。

```text
StartReview -> ReviewRunResult
ResumeReview -> ReviewRunResult
RequestPause / TerminateReview -> ControlRequestResult
RetryReportDelivery -> DeliveryResult
GetReviewProgress -> ReviewProgressView
```

命令和阶段动作均带 request ID、幂等键、指纹、task ID、预期版本；执行面再带 lease/fencing。同键同指纹返回原结果，同键异指纹冲突。

## 9. 测试与 ADR

测试阶段单调性、候选不可越过收敛、结果/交付正交、租约过期和旧 fencing、全部 UoW 故障点、unknown、暂停终止和幂等。
