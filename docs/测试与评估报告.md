### 真实测试发现与复验

首次真实运行依次暴露并修复了以下问题：

- 长路径和正文中的高熵字符串脱敏会破坏 unified diff 结构；现已保护路径元数据
  和 hunk 首列控制符，同时继续脱敏正文 secret。
- `+@respx.mock` 曾被邮箱规则误判；邮箱本地部分现要求至少包含字母或数字。
- 可安全脱敏的发布正文曾被直接拒绝；现先脱敏，再按脱敏后的精确正文重新生成
  publication key、摘要和隐藏标记。
- HTTPX 流式读取 gzip 响应后重建响应时曾发生二次解码；现移除已消费的
  `content-encoding/content-length`，并以分块方式执行响应字节上限。
- 发布计划读取现验证正文摘要、标记、snapshot/target 绑定和 item 数据库行；每次
  远端写入前再次执行安全扫描。
- 并发状态更新现校验单调 fencing token、租约 owner 和 item version CAS，旧发布者
  不能覆盖新租约持有者结果。

上述问题均有回归测试。最终重新执行 Ruff、Mypy、521 项 Pytest 和
`git diff --check`，全部通过。失败阶段没有向远端写入评论；只有状态为
`succeeded` 的尝试产生了上述 3 条测试评论。

## 已知限制

- 固定样例中的预期缺陷是验收夹具声明，不代表模型能发现所有未知缺陷。
- 企业自建 GitHub/GitLab 和多用户身份不在首版范围；远程回评仅支持
  GitHub.com/GitLab.com，且必须显式授权。
- 系统不执行被审查仓库的脚本、构建、测试、插件或依赖。
- 金额预算当前按配置的 CNY/百万 token 综合单价换算，不区分输入、输出或缓存 token
  的差异化单价。
