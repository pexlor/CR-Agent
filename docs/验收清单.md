# Code Review Agent 项目验收清单

## 1. 使用说明

本清单用于 Code Review Agent MVP 的最终验收。验收范围以《需求拆解.md》中的 C-001～C-023、FR-001～FR-028 和 BR-001～BR-015 为准；《开发流程.md》用于核对工程与交付材料。若本文与需求基线冲突，以最新、已确认的需求基线为准，并先更新本文后再继续验收。

### 1.1 结果标记

- `[ ]`：未执行或未确认。
- `[x]`：已通过，且证据栏已填写。
- `失败`：实际结果不满足判定标准。
- `阻塞`：因环境或依赖无法执行，不能按通过处理。
- `不适用`：仅限明确不在 MVP 范围内的项目，并须写明依据。

每个勾选项必须能关联到可复现证据。仅有口头确认、截图但无输入和版本信息、或一次不可复现的演示，不算通过。

## 2. 最终通过门禁

只有以下条件全部满足，项目才能判定为“通过”：

- [ ] 28 条 MVP/P0 需求全部通过：FR-001～FR-028。
- [ ] FR-025～FR-028 四项安全要求全部通过；安全项不得以“有条件通过”豁免。
- [ ] 至少 8 个版本固定、结果预先标注、可重复执行的样例全部完成验收。
- [ ] 固定样例覆盖 Python、JavaScript、TypeScript、缺陷变更和干净变更。
- [ ] 所有预置“高置信度”缺陷均被发现，干净样例没有高置信度误报。
- [ ] git diff、GitHub PR、GitLab MR 三种输入均完成 Markdown 报告交付闭环。
- [ ] 正常、失败、部分完成、恢复、预算耗尽和安全拦截路径均有证据。
- [ ] 报告、trace、checkpoint、日志、错误信息及演示材料中没有真实 secret 或模拟 secret 明文泄露。
- [ ] 按 README 在干净环境中从零完成一次可复现运行。
- [ ] 所有失败、阻塞、偏差和已知限制均已记录，并且不存在尚未解决的 P0 缺陷。
- [ ] FR-010 GitHub 和 GitLab 远程回评均完成真实平台验收；发布必须显式授权且重试不重复评论。

任一 P0 或安全门禁未通过时，最终结论必须为“不通过”。“有条件通过”只可用于不影响 P0 判定的材料性问题，并须记录整改项、负责人和期限。

## 3. 验收前置准备

### 3.1 基线与环境

- [ ] 固定被验收代码提交、依赖锁文件、配置示例和审查规则版本。
- [ ] 固定模型名称、模型配置及可核对 token 用量的测试方式。
- [ ] 准备隔离的 GitHub.com 和 GitLab.com 测试仓库，不使用生产仓库或真实敏感信息。
- [ ] 为 GitHub 和 GitLab 各准备一份满足读取与评论发布的最小权限共享测试凭证。
- [ ] 准备无凭证、失效凭证、权限不足凭证或等价可控故障环境。
- [ ] 确保测试能够模拟模型超时／限流、工具失败、平台临时失败、进程退出和机器重启。
- [ ] 确保能查看模型实际输入、trace、checkpoint 和预算记录，同时不扩大敏感信息暴露范围。
- [ ] 验收输入、预期发现、预期不发现内容及其文件哈希在执行前已固定。

### 3.2 证据要求

- [ ] 每次运行记录样例 ID、任务 ID、输入版本／哈希、代码版本、规则版本、开始和结束时间。
- [ ] 每个需求至少关联一项证据：测试记录、Markdown 报告、trace、checkpoint、预算账本或只读配置快照。
- [ ] 故障注入记录明确注入位置、预期行为和实际行为。
- [ ] 截图仅作辅助；关键结论可由文本记录、固定输入和运行结果复核。
- [ ] 证据中的 secret 均为模拟值并按产品规则脱敏；禁止把真实凭证收入验收包。
