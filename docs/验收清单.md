# Code Review Agent 项目验收清单

## 1. 使用说明

本清单用于 Code Review Agent MVP 的最终验收。验收范围以《需求拆解.md》中的 C-001～C-023、FR-001～FR-028 和 BR-001～BR-015 为准；《开发流程.md》用于核对工程与交付材料。若本文与需求基线冲突，以最新、已确认的需求基线为准，并先更新本文后再继续验收。

### 1.1 结果标记

- `[ ]`：未执行或未确认。
- `[x]`：已通过，且证据栏已填写。
- `失败`：实际结果不满足判定标准。
- `阻塞`：因环境或依赖无法执行，不能按通过处理。
- `不适用`：仅限明确不在 MVP 范围内的项目，并须写明依据。

每个勾选项必须能关联到可复现证据。仅有口头确认、截图但无输入和版本信息、或一次不可复现的演示，不算通过。

## 3. 验收前置准备

### 3.1 基线与环境

- [ ] 固定被验收代码提交、依赖锁文件、配置示例和审查规则版本。
- [ ] 固定模型名称、模型配置及可核对 token 用量的测试方式。
- [ ] 准备隔离的 GitHub.com 和 GitLab.com 测试仓库，不使用生产仓库或真实敏感信息。
- [ ] 为 GitHub 和 GitLab 各准备一份满足读取与评论发布的最小权限共享测试凭证。
- [ ] 准备无凭证、失效凭证、权限不足凭证或等价可控故障环境。
- [ ] 确保测试能够模拟模型超时／限流、工具失败、平台临时失败、进程退出和机器重启。
- [ ] 确保能查看模型实际输入、trace、checkpoint 和预算记录，同时不扩大敏感信息暴露范围。
- [ ] 验收输入、预期发现、预期不发现内容及其文件哈希在执行前已固定。

### 3.2 证据要求

- [ ] 每次运行记录样例 ID、任务 ID、输入版本／哈希、代码版本、规则版本、开始和结束时间。
- [ ] 每个需求至少关联一项证据：测试记录、Markdown 报告、trace、checkpoint、预算账本或只读配置快照。
- [ ] 故障注入记录明确注入位置、预期行为和实际行为。
- [ ] 截图仅作辅助；关键结论可由文本记录、固定输入和运行结果复核。
- [ ] 证据中的 secret 均为模拟值并按产品规则脱敏；禁止把真实凭证收入验收包。

## 5. P0 需求验收

### 5.1 E1 变更输入与范围确认

#### FR-001 接收 git diff

- [ ] UTF-8 unified diff 文本和文件均能接收，相同内容产生一致的审查对象。
- [ ] 一次任务只接受一种输入；空 diff 返回“无变更”。
- [ ] 纯删除和文件重命名可处理；二进制内容列为未审查且不声称完整覆盖。
- [ ] 超过 1 MiB、200 个文件或 10,000 个变更行的样例分别被拒绝并说明具体原因。
- [ ] 非 diff、损坏、编码不可识别和不可读取输入被明确拒绝。
- 证据：`evidence/test-runs/local-2026-09-13.md`记录了一次真实 Git 仓库 diff
  端到端 CLI 运行（`/tmp/cr-agent-e2e.GK8rnf/change.diff`），验证了 diff 文件
  输入路径可被接受并进入审查流程（Provider 返回 HTTP 401，结果为
  `partial`），但该证据只覆盖“diff 文件可被接受并触发审查”，未覆盖本条要求
  的一致性哈希、空 diff、重命名/二进制、超限拒绝、损坏输入拒绝等具体子项。
- 结果：未执行（仅有输入可被接受的旁证，具体子项未见专项证据）。

#### FR-002 接收 GitHub PR／GitLab MR 链接

- [x] GitHub.com PR 和 GitLab.com MR 均能获取公开仓库的完整、固定版本变更。
- [ ] 两个平台各配置一次共享只读凭证后，私有仓库审查无需用户逐次提供凭证。
- [ ] 本机可信用户可更新或清除共享凭证；新凭证仅影响之后启动或尚未发起平台请求的恢复任务。
- [x] Open 和 Draft 对象可处理；关闭和已合并对象被明确拒绝。
- [ ] 凭证未配置、失效、权限不足、对象不存在、平台不可用或 diff 不完整时分别明确失败。
- [ ] GitHub Enterprise Server、自建 GitLab 和其他域名被明确告知不支持。
- [ ] 不在共享凭证失败时自动尝试其他身份，任务期间不混入源对象的新提交。
- 证据：`docs/测试与评估报告.md`“真实 GitHub 远程回评”章节，真实 Draft PR
  `pexlor/CR-Agent#1` 固定 head `47259a18cc6adf5ed9273a35cc87c046b121b10b` 与
  `3a5300ad7aa2be087ff30a46d71f15cb6022def2`两次真实拉取并审查；`docs/AI协作案例.md`
  记录真实 GitHub PR 验证中发现并修复 rename 文件 diff 头和 `patch = null`
  二进制误判两个真实边界问题。GitLab 侧目前只有模拟 HTTP 契约测试
  （`docs/测试与评估报告.md`范围说明：“GitLab 远程发布目前只有模拟 HTTP 契约
  测试，尚未执行真实 MR 写入”），未见真实 GitLab.com MR 获取记录。
- 结果：GitHub.com 侧“获取 Open/Draft 固定版本变更”通过（真实证据）；GitLab.com
  侧真实 MR 获取未执行；共享凭证配置/更新/清除、凭证失败分类、企业版域名拒绝、
  身份混用防护等子项未见专项证据，未执行。

#### FR-003 校验输入并反馈不可处理原因

- [ ] 缺少输入、同时提供多种输入、内容损坏和仅部分可用均返回可区分的原因。
- [ ] 系统不猜测多种输入的优先级。
- [x] 输入未被接受时，不生成“已完成审查且未发现问题”的误导结果。
- 证据：`docs/测试与评估报告.md`记录真实端到端运行中 Provider 返回 HTTP 401
  时，系统生成报告并将结果标记为 `partial`，三个审查 scope 均记录为
  `unreviewed(provider_http_401)`，未将失败伪装成 `complete_no_findings`；
  `docs/六项能力测试报告-真实模型.md`第4节预算拦截场景同样返回
  `task result=partial`、`unreviewed (budget_reservation_rejected)`，而非
  伪装完成。这两个案例证明“失败不伪装为完整无发现”，但均属于执行期失败而非
  本条要求的输入校验期原因区分（缺失/多输入/损坏/部分可用）。
- 结果：不伪装误导结果这一项通过（有真实案例支撑）；缺少输入、多输入同时
  提供、损坏、部分可用的具体原因区分未见专项证据，未执行。

#### FR-004 明确本次审查对象与范围

- [ ] 报告可核对独立 diff 的输入标识，或平台对象启动时的固定提交版本。
- [x] 已审查、未审查、不可处理部分及限制在结果中明确可见。
- [ ] 只按需读取同一版本的相关文本文件，不读取二进制上下文。
- [ ] 审查期间源对象变化时，旧版本结论不会冒充新版本结论。
- 证据：`docs/测试与评估报告.md`记录 HTTP 401 场景下三个审查 scope 均明确记录
  为 `unreviewed(provider_http_401)`；真实模型编排复验（task
  `b91c1459-9528-497c-8543-3fb7654837e5`）明确将已完成、未知和未完成范围分别
  标记为 `reviewed`、`unknown`、`unreviewed`。
- 结果：已审查/未审查/不可处理部分可见这一项通过；输入标识核对、二进制上下文
  不读取、源对象变化时结论不混用等子项未见专项证据，未执行。

#### FR-005 基于变更识别审查问题

- [ ] 固定样例覆盖 Python、JavaScript、TypeScript 的正确性、安全、可靠性和明显性能问题。
- [ ] 所有预置高置信度缺陷均被发现，干净样例不产生高置信度误报。
- [ ] 只评论本次变更新增或明显加剧的问题，不评论无关既有问题。
- [ ] 不输出纯格式、个人偏好型风格评论；可维护性评论能说明行为影响或维护风险。
- [x] 无有效问题时允许零评论，不为满足数量而编造问题。
- 证据：`docs/六项能力测试报告-真实模型.md`第5节，本次真实模型审查全部 21
  条发现均为 `advisory`，如实反映当前工具链限制而非编造更高置信度问题；
  `docs/测试与评估报告.md`记录固定样例矩阵覆盖 AC-01～AC-14（见
  `tests/acceptance/test_acceptance_matrix.py`），但报告明确说明“固定样例测试
  当前验证 fixture/manifest 和领域矩阵，尚未对每个样例执行真实 Provider
