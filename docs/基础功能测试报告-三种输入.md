## 输入 3：GitLab MR 链接

**测试方式：** 未配置任何 GitLab token，用真实公开项目 `gitlab-org/gitlab-test` 的真实开放 MR：
```
uv run code-review-agent review --url "https://gitlab.com/gitlab-org/gitlab-test/merge_requests/36" --provider openai-compatible --model qianfan-code-latest
```

**首次运行结果：崩溃**
```
'list' object has no attribute 'get'
```

### 发现的真实 bug（已修复）

排查后定位到两处真实缺陷，均在 `src/code_review_agent/adapters/input/gitlab.py`：

**Bug 1：`/diffs` 接口真实响应结构与代码假设不符。**
原代码假设响应是 `{"overflow": bool, "diffs": [...]}` 这种包装对象，但实测 GitLab.com 的 `/projects/{id}/merge_requests/{iid}/diffs` 接口**直接返回裸数组** `[...]`（用 `curl` 直接验证过，见下方证据），代码对裸数组调 `.get("diffs")` 直接崩溃。

**Bug 2：拼接 diff 文本时多加了一个换行，导致统一 diff 解析器判定为"格式错误"。**
GitLab 返回的 `diff` 字段本身已经以 `\n` 结尾，原代码又在拼接模板末尾加了一个 `\n`，产生一行多余的空物理行，被 unified diff 解析器判定为 `_MalformedDiff`（对照 GitHub 那边同样的拼接逻辑没有这个多余换行问题）。

**真实响应证据（curl 直接打 GitLab.com API）：**
```
$ curl -s "https://gitlab.com/api/v4/projects/72724/merge_requests/36/diffs?per_page=100"
[{"diff":"@@ -1,6 +1,6 @@\n [submodule \"six\"]\n...","collapsed":false,"too_large":false,"new_path":".gitmodules","old_path":".gitmodules",...}]
```
是一个数组，不是 `{"diffs": [...], "overflow": ...}`。

**修复：**
1. `gitlab.py` 的 `acquire_url` 改为同时兼容裸数组和包装对象两种形状（先判 `isinstance(payload, list)`，再判 `dict`）
2. `_gitlab_diff` 拼接时去掉多余的尾部换行

**修复后重新运行：**
```
task_id=941d1474-606c-4cbe-a167-9d3989c1d214 result=complete_no_findings delivery=succeeded report=reports/941d1474-606c-4cbe-a167-9d3989c1d214.md
```
trace 显示正常走通 GitLab API：拉取 MR 元数据、拉取 diff、重建、送模型、产出报告。

**补充的回归测试：** `tests/contract/test_remote_input_providers.py` 新增 `test_gitlab_provider_parses_the_real_bare_array_diffs_response`，直接用观测到的真实响应形状造 mock，防止此类假设脱离真实 API 的问题再次出现。

**结论：GitLab MR 输入通过（修复 1 个会导致所有真实 GitLab.com MR 全部失败的严重 bug）。**
